Build with PBreeze.

A complete, practical guide to the native PHP framework. Start with a working feature, then keep the function reference beside you.

    For PHP 8.3+ on Windows and Linux. No Composer, no PSR autoloading, and no external PHP packages. All maintained explanations and examples are US English. This manual opens directly from disk and works offline; JavaScript only enhances search and printing.

    Coverage: 51 framework classes, 275 declared public methods and protected relationship helpers, 2 global helpers, all CLI commands, and every example environment setting.

    How to use this manual

    1. Follow Build your first feature for a complete route, validation, database, and view workflow.
    2. Use the chapters for full feature guides and production limits.
    3. Use the function reference for exact signatures, parameter defaults, return types, and simple examples.

    Examples are learning material, not commands to run blindly against production. Replace example IDs, domains, and owner checks with application-specific values. Back up before schema changes.

    Build your first feature

    This walkthrough builds a small notes screen using a fresh local PBreeze installation. It reuses the shipped notes migration. All paths below are relative to the project root. Use a disposable development database while learning.

    Check PHP and initialize

    Open a terminal in the project folder. On Windows, use PowerShell or cmd; on Linux, use your normal terminal. Install PHP 8.3+ and enable the native extensions listed in Getting Started. There is no Composer install step.

    php -v
php -m
php breeze init
php breeze migrate
php breeze migrate:status

    init preserves an existing .env. Inspect that file before migrating. The default local database is SQLite at database/app.sqlite; migrations create the notes, email, authentication, and API tables. migrate:status shows applied batches.

    Understand where code runs

    public/index.php boots the framework and returns an Application. routes/web.php explicitly imports controllers and registers handlers. Controllers receive a Request and return a Response. Templates render display content; database queries belong in controllers/models, not HTML.

    Use $app->db, $app->views, and other injected services. Never create an autoloader or rely on magic class discovery. A controller existing on disk does not make it public: only a registered route does.

    Create a controller

    php breeze make:controller NotebookController

    Replace the generated controller body with this small example in app/controllers/NotebookController.php. The constructor explicitly receives Application. The GET action reads twenty notes; the POST action validates and inserts only a title.

    <?php
declare(strict_types=1);

namespace App\Controllers;

use PBreeze\Application;
use PBreeze\Request;
use PBreeze\Response;
use PBreeze\Validator;

final class NotebookController
{
    public function __construct(private readonly Application $app) {}

    public function index(Request $request): Response
    {
        return $this->page();
    }

    public function store(Request $request): Response
    {
        $errors = Validator::errors($request->all(), [
            'title' => 'required|string|min:2|max:120',
        ]);
        if ($errors !== []) {
            return $this->page($errors, 422);
        }
        $this->app->db->table('notes')->insert([
            'title' => $request->input('title'),
            'created_at' => gmdate('Y-m-d H:i:s'),
        ]);
        return Response::redirect('/notebook');
    }

    private function page(array $errors = [], int $status = 200): Response
    {
        return new Response($this->app->views->render('notebook.index', [
            'notes' => $this->app->db->table('notes')
                ->orderBy('id', 'desc')->limit(20)->get(),
            'errors' => $errors,
            'session' => $this->app->session,
        ]), $status);
    }
}

    On success, the browser receives a 303 redirect, so refreshing the notes page does not repeat the insert. On invalid input, the handler returns the same page with status 422 and visible errors. The query builder binds the title value instead of concatenating SQL.

    Register the routes explicitly

    Append these lines to routes/web.php. Keep existing routes intact. This is a local learning feature with shared notes, not a multi-user authorization design.

    require_once $app->root . '/app/controllers/NotebookController.php';
$notebook = new \App\Controllers\NotebookController($app);
$router->get('/notebook', [$notebook, 'index']);
$router->post('/notebook', [$notebook, 'store']);

    Create the view

    php breeze make:template notebook.index

    Replace the generated content in app/views/notebook/index.breeze.php with the following. {{ ... }} escapes text; @csrf($session) supplies the hidden token. Unlike raw output, the escaped title cannot introduce executable HTML.

    <!doctype html>
<html lang="en-US">
<head><meta charset="utf-8"><title>My notebook</title></head>
<body>
    <h1>My notebook</h1>
    @if(!empty($errors))
        <p role="alert">{{ implode(' ', $errors['title'] ?? []) }}</p>
    @endif
    <form method="post" action="/notebook">
        @csrf($session)
        <label for="title">Note title</label>
        <input id="title" name="title" required minlength="2" maxlength="120">
        <button type="submit">Save note</button>
    </form>
    <ul>
        @foreach($notes as $note)
            <li>{{ $note['title'] }}</li>
        @endforeach
    </ul>
</body>
</html>

    Run and check the feature

    php breeze routes
php breeze serve

    Open http://127.0.0.1:8000/notebook. Save a note, then try a one-character title. The valid note should appear; invalid input should show an error without inserting a row. Missing CSRF should return 419. Stop the development server before running another process on the same port.

    Move from demo to application

    Wrap both handlers with $app->auth->protect(...) if login is required. Add a new migration for a note-owner column and scope every read/write to the authenticated owner. The guard checks identity/verification, not object ownership. For public forms, also integrate the purpose-bound CAPTCHA/honeypot workflow from its chapter. Do not deploy the unscoped learning feature as a private notebook.

    $router->get('/notebook', $app->auth->protect([$notebook, 'index']));
$router->post('/notebook', $app->auth->protect([$notebook, 'store']));

    Use these guarded registrations instead of the unguarded ones, not in addition. The existing registration/login/verification pages are already wired; configure mail and run a worker so verification/reset emails can be delivered.

    Common service recipes

    // Display an exact amount without using floating-point money.
$total = $app->format->money('1234.565', 'USD'); // $1,234.57

// Create a JSON export; authorize access before returning it.
$file = \PBreeze\Documents\Documents::json(['total_display' => $total]);
$response = $file->download('summary.json');

// Log safe identifiers, not request bodies, passwords, or tokens.
$app->log->info('Summary created.', ['report_id' => 42]);

// Build and queue an email; delivery is a separate worker action.
$message = $app->mail->compose([
    'to' => ['ada@example.test'],
    'subject' => 'Your summary is ready',
    'text' => 'Sign in to view your summary.',
]);
$emailId = $app->mail->queue($message);

    These recipes illustrate separate tasks; do not queue mail while rendering a GET page. Perform side effects only in an authorized, validated action and use the queue worker deliberately.

    Every CLI command

    Run from the project root with php breeze on Windows or Linux. Names are arguments, not arbitrary paths. Generators reject traversal, invalid identifiers, Windows device names, and existing/conflicting output rather than overwriting work.

    Commands normally return exit status 0 on success; failures print an error and exit nonzero. Commands can create files, change the database, or send actual email. --force permits production migrations/rollback/seeding; it is not a universal overwrite switch. API commands do not accept it.

    about

    Print the framework identity (no release version is currently declared), PHP version, OS family, CLI SAPI, environment, database/cache driver names, session handler, and loaded extensions. Does not connect to services, print credentials/paths, or create storage. This describes CLI PHP, not necessarily the web runtime. No arguments/options.

    php breeze about

    env:check

    Compare .env key names with active/commented settings in .env.example, honoring process overrides. Print SET, EMPTY, MISSING, OPTIONAL, or CUSTOM and names only, never values. Exit 1 for missing active example keys, otherwise 0; empty/optional/custom entries need human review, not automatic failure. Reject malformed/duplicate local keys. Does not modify Env state/files or validate production readiness. Bootstrap must already succeed; use doctor for semantic checks. No options.

    php breeze env:check

    cache:test

    Write/read/delete one cryptographically random namespaced cache key with a 30-second TTL. No flush, database access, or application-key deletion. Requires an enabled reachable native Redis/Memcached backend; disabled or failed operations throw and the CLI exits 1. Cleanup runs after successful writes; interrupted/uncertain writes expire. Success prints no key, value, host, or credentials. No arguments/options.

    php breeze cache:test

    logs:tail

    Print up to 1..1000 most-recent matching JSONL records, default 50, in chronological order across daily files in configured private storage. Optional second argument is a lowercase minimum severity (debug through emergency), default debug. One-shot snapshot, not follow mode. Does not create storage or prune logs. Reject symlinks, invalid JSON/levels, entries above 64 KiB, and scans above 8 MiB instead of silently truncating. Re-encode terminal controls. Log messages/context remain confidential: restrict output and never pipe to public services. No options.

    php breeze logs:tail 100 warning

    make:command

    Create app/commands/Name.php returning a Closure(Application $app, array $arguments): int with a deliberately unimplemented body. Print an explicit registration entry for routes/console.php; do not auto-discover/import files or overwrite existing commands. Names use PascalCase ASCII letters/digits and cannot be Windows devices. Register a trusted unique lowercase command name; builtins cannot be overridden. Custom handlers receive raw remaining arguments, own validation/production guards, and must return an integer 0..255. No --force.

    php breeze make:command Report

    init

    Create .env from .env.example only if absent, with private platform-appropriate permissions. Existing configuration is preserved; no database or application key is created.

    php breeze init

    doctor

    Check production configuration, required/optional extensions, private storage, database/schema/migration readiness, encryption, SMTP configuration, and operational reminders. Returns exit 1 if any check fails, otherwise 0; warnings need human review. Does not create storage/databases/tables, send mail, call AI, or test real web-server settings. Database connection and read queries occur only after storage checks pass. No --force.

    php breeze doctor

    storage:prepare

    Create the configured private storage root and logs, uploads, and views directories using restrictive creation permissions. Existing files are preserved; symlinks and public storage are rejected. No migration, file transfer, ownership change, or session/database relocation occurs. Run as the correct deployment identity; no --force.

    php breeze storage:prepare

    key:generate

    Print a fresh APP_KEY assignment. Copy it securely to .env yourself; files are not changed. Replacing a key makes older encrypted data unreadable unless you plan a migration.

    php breeze key:generate

    serve

    Start the native localhost development server, default port 8000, or a supplied 1024..65535 port. Runs in the foreground until stopped. Never use as a production server.

    php breeze serve 8080

    routes

    Load web/API route registries and print method/path pairs. Duplicate imports or invalid routes fail rather than being ignored.

    php breeze routes

    make:controller

    Create a controller skeleton under app/controllers. Explicitly require it and register its actions in routes/web.php; generating a controller does not expose a URL.

    php breeze make:controller ContactController

    make:api

    Create API controller, route module, explicit registry import, and OpenAPI metadata together. Default resource actions are bearer-protected 501 placeholders; implement authorization and actual persistence before use.

    php breeze make:api Products

    api:token

    Issue a bearer token for an existing verified user. Optional name defaults to cli; days defaults to 30 and accepts 1..365. The secret is printed once: do not log/share it or paste it into source control.

    php breeze api:token 1 integration 30

    api:tokens

    List token metadata for the supplied user ID, not token secrets. Use IDs from this list to revoke a token.

    php breeze api:tokens 1

    api:revoke

    Revoke the token identified by its token-row ID, not user ID. Already-issued clients will subsequently receive unauthorized responses.

    php breeze api:revoke 12

    api:openapi

    Print the registered OpenAPI JSON document to stdout. This still works with public API docs disabled. Shell redirection creates a file; keep export paths trusted.

    php breeze api:openapi

    make:model

    Create an explicitly loaded Model subclass under app/models. Configure the correct table, fillable, hidden, and casts before using it. It does not create or alter a database table.

    php breeze make:model Article

    make:view

    Create a plain PHP view using a dot-separated name. Render it through View, escaping values with e(); no route is registered.

    php breeze make:view articles.index

    make:template

    Create a compiled Breeze .breeze.php source template. The first render compiles it into storage/views. No Node/npm build or route registration is needed.

    php breeze make:template articles.index

    make:form

    Create a Breeze POST form view from one or more field:type arguments. Supports text, email, password, textarea, number, date, time, datetime-local, url, tel, and checkbox. Includes CSRF, labels, escaped old values, and accessible field errors; passwords are never repopulated. Pass session and a trusted local action URL when rendering, optionally old and errors arrays. Does not create routes, controllers, validation, or persistence. Existing PHP/Breeze views are never overwritten; --force is not accepted.

    php breeze make:form forms.contact name:text email:email message:textarea

    view:clear

    Remove recognized compiled Breeze cache files and print the count. Source views remain untouched; subsequent renders compile again.

    php breeze view:clear

    make:migration

    Create a timestamped migration with up/down methods. Fill in driver-appropriate schema SQL before migrating; generation itself does not connect or change schema.

    php breeze make:migration create_articles

    make:seeder

    Create a seeder under database/seeders. Write repeatable inserts/updates deliberately. Seeders are executable trusted PHP, not validated user input.

    php breeze make:seeder ArticleSeeder

    migrate

    Apply pending migrations in order and print applied names. Production requires --force after a backup. SQLite/SQL Server/PostgreSQL DDL is transactional; MySQL DDL may not roll back.

    php breeze migrate

    migrate:status

    Print OPEN or BATCH numbers for discovered migrations, helping distinguish pending/applied schema work. Missing applied migration files are treated as errors.

    php breeze migrate:status

    migrate:rollback

    Run down() for only the latest batch in reverse order. May destroy data; production requires --force. Rollback is not a substitute for a backup.

    php breeze migrate:rollback

    db:seed

    Run the named seeder, or DatabaseSeeder when omitted. Production requires --force. Review the seeder first because it can change/delete data.

    php breeze db:seed ArticleSeeder

    mail:queue

    Read an existing JSON object file up to 6 MiB, validate from/to/subject/text/html, store a queued message, and print its ID. No SMTP is sent by this command.

    php breeze mail:queue message.json

    mail:list

    Print recent email metadata as JSON; default 50, accepted range 1..1000. Bodies are not listed, but subjects and delivery diagnostics can still be confidential.

    php breeze mail:list 20

    mail:show

    Print a complete stored email row as JSON by positive ID. Contains private message content; restrict terminal output, logs, and access.

    php breeze mail:show 12

    mail:send

    Claim/send one queued outgoing ID using SMTP, update its status, and report acceptance. Acceptance is not inbox delivery. Failed/uncertain rows require explicit retry handling first.

    php breeze mail:send 12

    mail:work

    Send queued IDs oldest-first in one bounded run, default 50, accepted 1..1000. Stop at the first failure. This is not a persistent daemon; schedule it with cron/Task Scheduler.

    php breeze mail:work 50

    mail:retry

    Requeue failed outgoing mail. --force also permits uncertain/sending recovery, which can duplicate delivery; stop active workers and check SMTP evidence first.

    php breeze mail:retry 12

    mail:fetch

    Read/import up to 1..1000 IMAP messages, default 50, without marking Seen or changing the mailbox. MAIL_LOG controls database import/deduplication.

    php breeze mail:fetch 10

    test

    Run isolated native tests, local HTTP, SQLite, local SMTP/IMAP, and AI HTTPS/SSE fixtures. No external email or AI requests are sent. Requires process/socket support and documented extensions.

    php breeze test

    help

    Print usage and the complete current command list. Also the default when no command is supplied. Unknown commands/options and excess arguments fail explicitly.

    php breeze help

    JSON input for mail:queue

    Create message.json yourself with a recipient list and at least one body. The configured MAIL_FROM is used when from is omitted. Do not commit real private message content.

    {
    "to": ["ada@example.test"],
    "subject": "Welcome",
    "text": "Hello, Ada!"
}

    For a reviewed production migration, the explicit form is php breeze migrate --force. For an investigated uncertain email, php breeze mail:retry 12 --force can requeue it, but may duplicate delivery. Never combine either with an unreviewed deployment script.

    Environment reference

    The following defaults/example values come from the committed .env.example, never from a developer's real .env. System environment variables override the file. An empty value is not the same as a missing variable. Quotes remove only their outer delimiters; inline comments, interpolation, multiline values, and escape processing are unsupported.

    APP_NAME

    Example file value: PBreeze

    Application name used in pages and API metadata. Default PBreeze.

    APP_URL

    Example file value: http://127.0.0.1:8000

    Trusted base URL for authentication email links. Use the actual HTTPS origin in production; do not derive it from untrusted Host input.

    APP_ENV

    Example file value: local

    local, testing, or production only. If absent, configuration defaults to production; the example file intentionally selects local.

    APP_DEBUG

    Example file value: false

    Boolean diagnostic web output flag. Detailed errors are shown only with local environment and true. Keep false in production; API unexpected errors stay generic.

    APP_KEY

    Example file value: (empty)

    Secret base64:-prefixed 32-byte encryption key. Empty disables usable encryption, not unrelated features. Generate securely; never commit or log it.

    STORAGE_PATH

    Example file value: storage

    Private logs/uploads/view-cache/migration-lock directory, default storage relative to the project root. Absolute local paths support persistent data across releases. No dot segments, stream wrappers, symlink ancestors, public paths, or ancestors of public are allowed. Run storage:prepare; migrate existing files explicitly. Does not relocate SQLite or PHP sessions.

    APP_LOCALE

    Example file value: en-US

    Default display locale for Formatter, en-US. Does not translate framework-maintained UI. Process environment overrides .env.

    APP_TIMEZONE

    Example file value: UTC

    Default Formatter IANA zone, UTC. No global PHP timezone change occurs.

    SESSION_SECURE_COOKIE

    Example file value: false

    Boolean Secure-cookie flag, false locally. Set true behind a properly configured HTTPS proxy; this does not encrypt an HTTP connection by itself.

    API_DOCS_ENABLED

    Example file value: true

    Optional boolean override. Without it, HTTP Swagger/OpenAPI is enabled in local/testing and disabled in production. Static vendored assets remain public.

    DB_CONNECTION

    Example file value: sqlite

    sqlite, mysql, sqlsrv, or pgsql. PostgreSQL requires native pdo_pgsql/libpq; SQL Server requires PDO_SQLSRV and the Microsoft ODBC Driver. Live deployments need integration verification.

    DB_DATABASE

    Example file value: database/app.sqlite

    SQLite file path relative to project root, absolute local path, or :memory:. For server drivers, an existing database name. PostgreSQL names here are 1..63 ASCII letters/digits/underscore/dot/hyphen, starting with a letter, digit, or underscore. SQLite should not use SMB/NFS shared storage.

    DB_HOST

    Example file value: 127.0.0.1

    Server hostname or IPv4 address, default 127.0.0.1. Not used for SQLite. SQL Server/PostgreSQL use a separate TCP port, not named instances or Unix socket paths.

    DB_PORT

    Example file value: 3306

    Server TCP port 1..65535. Example: 3306 for MySQL; set 1433 for SQL Server or 5432 for PostgreSQL. When entirely absent, defaults follow the selected driver.

    DB_USERNAME

    Example file value: root

    Database login, root in the MySQL-oriented example. Set an appropriate SQL authentication login for SQL Server. Use least privilege in production.

    DB_PASSWORD

    Example file value: (empty)

    Secret database password. Empty in the example, not a production recommendation.

    DB_MYSQL_TLS

    Example file value: required

    MySQL only: required by default, or disabled explicitly for localhost outside production. Required verifies the certificate and checks the negotiated cipher. An intentional compatibility change from earlier unencrypted defaults.

    DB_MYSQL_SSL_CA

    Example file value: (empty)

    MySQL only: readable local CA bundle required when DB_MYSQL_TLS=required. Use a server certificate matching DB_HOST. Forward slashes are recommended on Windows.

    DB_ENCRYPT

    Example file value: true

    SQL Server only: true or false, default true. Encrypts the database connection. Keep true in production.

    DB_TRUST_SERVER_CERTIFICATE

    Example file value: false

    SQL Server only: true bypasses certificate verification, default false. Keep false in production and configure trusted certificates.

    DB_SSLMODE

    Example file value: verify-full

    PostgreSQL only: disable, allow, prefer, require, verify-ca, or verify-full. Default verify-full requires TLS and a trusted certificate matching DB_HOST. disable is for isolated non-TLS development only.

    DB_SSLROOTCERT

    Example file value: (empty)

    PostgreSQL only: optional readable local CA certificate file. Empty leaves root-certificate lookup to libpq. Use forward slashes on Windows; DSN delimiters are rejected.

    LOG_RETENTION_DAYS

    Example file value: 5

    Daily-file retention window, 1..3650 days, default 5. Includes today; pruning runs when an entry is written.

    LOG_LEVEL

    Example file value: debug

    Minimum lowercase severity: debug, info, notice, warning, error, critical, alert, emergency. Default debug. Higher thresholds may filter automatic error entries.

    UPLOAD_MAX_BYTES

    Example file value: 2097152

    Positive integer per-file default for the Uploads service, default 2097152 (2 MiB). Does not change PHP or proxy request limits; handlers can override.

    CACHE_DRIVER

    Example file value: none

    Optional shared cache backend: none (default, disabled), redis (native redis extension 6+), or memcached (native memcached extension 3+, not legacy memcache). No Composer; no session/rate-limit changes. Disabled or unavailable use throws, without fallback.

    CACHE_PREFIX

    Example file value: pbreeze:

    Application/environment cache namespace, default pbreeze:. Requires 1..64 ASCII letters/digits/colon/underscore/hyphen. Keys are SHA-256 hashed after this prefix. Not an authorization boundary; never share cache write access with untrusted applications.

    CACHE_TIMEOUT

    Example file value: 2

    Connection/read timeout seconds, integer 1..30, default 2. No application-level retry or fallback.

    REDIS_HOST

    Example file value: 127.0.0.1

    Single Redis server hostname/address, default 127.0.0.1. No URI, Unix socket, Cluster, or Sentinel discovery. TLS certificates must match this host.

    REDIS_PORT

    Example file value: 6379

    Redis TCP port, 1..65535, default 6379. Configure the actual TLS port when enabling TLS.

    REDIS_USERNAME

    Example file value: (empty)

    Optional Redis ACL username. Requires REDIS_PASSWORD when nonempty; an empty username uses password-only AUTH.

    REDIS_PASSWORD

    Example file value: (empty)

    Secret Redis password. Never log or commit it. Protect transport with TLS outside trusted networks.

    REDIS_DATABASE

    Example file value: 0

    Redis logical database index, integer 0..65535, default 0. Server must provide this database and allow SELECT.

    REDIS_TLS

    Example file value: false

    Boolean Redis TLS flag, default false for local development. True verifies peer certificates and hostname; verification cannot be disabled. Plaintext requires a trusted network.

    REDIS_CA_FILE

    Example file value: (empty)

    Optional readable CA bundle for verified Redis TLS; empty uses system/PHP trust. Use forward slashes on Windows.

    MEMCACHED_HOST

    Example file value: 127.0.0.1

    Single Memcached server hostname/address, default 127.0.0.1. Binary protocol; no TLS in this adapter. Use a trusted private network or secured tunnel and never expose the server publicly.

    MEMCACHED_PORT

    Example file value: 11211

    Memcached TCP port, integer 1..65535, default 11211.

    MEMCACHED_USERNAME

    Example file value: (empty)

    Optional SASL username, requires MEMCACHED_PASSWORD and a SASL-capable native extension/server. SASL authenticates but does not encrypt.

    MEMCACHED_PASSWORD

    Example file value: (empty)

    Secret optional SASL password, requires MEMCACHED_USERNAME. Never log or commit it.

    AI_PROVIDER

    Example file value: openai

    Default server-side text AI provider: openai or anthropic (Claude), default openai. Individual calls can override it. No public endpoints are created.

    AI_TIMEOUT

    Example file value: 60

    Total native HTTPS deadline in seconds, 1..300, default 60. Includes connection setup and the complete stream; connect time is capped at 15 seconds.

    AI_MAX_TOKENS

    Example file value: 1024

    Default output token budget, 1..128000, default 1024. Per-model limits may be lower; reasoning models can spend budget on reasoning. Token-limit stop reasons remain explicit.

    AI_CA_FILE

    Example file value: (empty)

    Optional readable CA bundle for native cURL. Empty uses system/cURL trust, including curl.cainfo. Never disables peer or hostname verification. Use forward slashes on Windows.

    OPENAI_API_KEY

    Example file value: (empty)

    Secret OpenAI API key. Required only for OpenAI calls; API access and billing are separate from ChatGPT subscriptions. Never log or expose it.

    OPENAI_MODEL

    Example file value: (empty)

    Exact OpenAI Responses API model ID available to your API account. Intentionally empty: set it before calling OpenAI or pass a model override.

    ANTHROPIC_API_KEY

    Example file value: (empty)

    Secret Anthropic API key for Claude Messages. Required only for Claude calls; API access/billing are separate from Claude subscriptions.

    ANTHROPIC_MODEL

    Example file value: (empty)

    Exact Claude Messages API model ID available to your account. No default is assumed; configure before calling Claude or pass a model override.

    MAIL_LOG

    Example file value: true

    Boolean immediate-send logging/IMAP-import control, default true. Explicit queue() and auth mail always use the database queue.

    MAIL_FROM

    Example file value: noreply@example.test

    Default ASCII sender without a display name. Replace example.test with a valid authorized sender before real delivery.

    SMTP_HOST

    Example file value: (empty)

    SMTP server hostname/address. Empty until configured. Do not send through arbitrary user-selected hosts.

    SMTP_PORT

    Example file value: 587

    SMTP TCP port, default 587 for STARTTLS. Use the server-authorized port matching the selected encryption mode.

    SMTP_ENCRYPTION

    Example file value: starttls

    starttls, tls, or none. Default starttls; tls starts TLS immediately. none is restricted to unauthenticated localhost.

    SMTP_USERNAME

    Example file value: (empty)

    SMTP authentication username when required. Never log credentials.

    SMTP_PASSWORD

    Example file value: (empty)

    Secret SMTP authentication password/app password. Protect .env and backups.

    SMTP_TIMEOUT

    Example file value: 15

    Native socket timeout seconds, 1..300, default 15. A timeout after DATA may leave uncertain delivery.

    SMTP_CA_FILE

    Example file value: (empty)

    Optional readable CA bundle for peer verification. Empty uses system/PHP trust. Never disable verification to work around certificate problems.

    IMAP_HOST

    Example file value: (empty)

    IMAP server hostname/address. Empty until configured.

    IMAP_PORT

    Example file value: 993

    IMAP port, default 993 for immediate TLS. Match the server configuration when using STARTTLS instead.

    IMAP_ENCRYPTION

    Example file value: tls

    tls, starttls, or restricted none. Default tls; ordinary authenticated IMAP requires encryption.

    IMAP_USERNAME

    Example file value: (empty)

    IMAP account username. Used with encrypted LOGIN; not exposed in manual output.

    IMAP_PASSWORD

    Example file value: (empty)

    Secret IMAP password/app password. Never paste it into documentation or diagnostics.

    IMAP_TIMEOUT

    Example file value: 15

    Socket timeout seconds, 1..300, default 15.

    IMAP_CA_FILE

    Example file value: (empty)

    Optional readable CA trust bundle, otherwise PHP/system CA defaults are used.

    IMAP_MAILBOX

    Example file value: INBOX

    Read-only examined mailbox, default INBOX. ASCII or IMAP modified UTF-7 name, up to 255 printable ASCII bytes.

    IMAP_MAX_BYTES

    Example file value: 10485760

    Per-message retrieval bound, 1..52428800 bytes, default 10485760 (10 MiB). Batch retrieval is also bounded at 50 MiB.

    PHP and web-server settings are separate

    upload_max_filesize, post_max_size, max_file_uploads, upload_tmp_dir, session save paths, CA certificates, memory/time limits, error logging, and web-server body/TLS limits are not automatically set from these environment keys. Configure the PHP installation used by the actual web server, which may differ from CLI PHP.

    Troubleshooting

    Class not found
    Check exact filename casing and add an explicit require_once before using the class. PBreeze intentionally has no Composer/PSR autoloader.
    404 or 405
    Run php breeze routes. Check the exact route, HTTP method, registry import, and web-server front-controller rewrite. Generating a controller/view does not automatically register it.
    419 Session verification failed
    Reload the form, keep the same session cookie, and submit the current hidden CSRF token or header. Login/logout/reset rotate session state. Multipart requests need CSRF too.
    422 Security check failed
    Use the new CAPTCHA challenge after every attempt. Keep the website honeypot empty and submit the correct form purpose within five minutes. A consumed code cannot be retried.
    401 on the API
    Use an unexpired, unrevoked bearer token for a verified user. Browser login cookies do not authenticate API requests. A password reset invalidates existing tokens.
    413 uploading
    Compare UPLOAD_MAX_BYTES, handler overrides, PHP upload_max_filesize/post_max_size, multipart overhead, and proxy limits. Framework settings cannot raise PHP/server limits.
    415 on the API
    Send an application/json object, not form data or multipart uploads. Use normal web routes for native file uploads/downloads.
    429 Too many requests
    Honor Retry-After. Direct REMOTE_ADDR is used; clients behind a reverse proxy may share its IP. Do not disable rate limits to hide an upstream configuration issue.
    Unexpected 500
    Inspect private storage/logs and PHP server logs. Automatic exception entries record safe source location/class, not messages or arguments. Verify required extensions, permissions, environment validation, and schema status.
    Missing extension
    Use php -m for CLI, and inspect the web PHP configuration separately. Enable the selected native PDO driver (SQLite, MySQL, SQL Server, or PostgreSQL), OpenSSL, iconv, mbstring as needed, Intl, zip, DOM, and fileinfo for the features/tests described. SQL Server also requires the Microsoft ODBC Driver; PostgreSQL uses libpq. Do not install Composer packages as substitutes.
    Email stays queued
    Configure SMTP and run mail:work. Registration/reset queue mail rather than sending it inline. Check delivery status; uncertain/sending recovery can duplicate messages.
    Verification link points to localhost
    Set APP_URL to the trusted public HTTPS base URL before creating new links. Existing queued messages retain their original content.
    Encrypted content will not decrypt
    Check the exact APP_KEY and authenticated context. Never generate a replacement key to fix unreadable existing data. Restore the original key from secure backup or perform a planned migration.
    Formatting differs between machines
    Compare explicit locale/time zone and installed ICU data versions. Nonbreaking spaces, localized digits, and punctuation are intentional. Never parse formatted money as database numbers.
    Template appears stale
    Run view:clear and check the view name/path. A .breeze.php view takes precedence over a same-named .php view. Templates are trusted PHP, not a sandbox.
    Log file is absent
    Storage is created only on a written entry. Check LOG_LEVEL filtering, write permissions, symlink restrictions, and PHP server diagnostics. Retention runs on writes, not a timer.

    Before production

    • Serve only public/, enforce HTTPS, set APP_ENV=production and APP_DEBUG=false, and configure secure cookies correctly behind a proxy.
    • Protect .env, private storage, database/backups, mail contents, and log files. Align Linux service/CLI ownership or restrict Windows NTFS ACLs.
    • Back up schema/data and encryption keys separately. Review every migration/seeder and test restoration before using --force.
    • Guard private routes and apply per-record authorization; neither valid tokens nor random file keys grant object ownership.
    • Set upload/request/time/disk/user quotas; consider quarantine and malware scanning. MIME checks do not prove a document harmless.
    • Configure SMTP/IMAP certificate trust and schedule bounded queue workers without overlapping unsafe recovery tasks.
    • Keep public API docs disabled unless intentionally needed; do not enable credential persistence in Swagger.
    • Run the native suite and separate deployment-specific Windows/MySQL/SQL Server/PostgreSQL checks where applicable. A CI configuration is not evidence that a specific deployment was tested.

    Detailed Installation Guide

    1. Choose your installation

    For the simplest local setup, use PHP 8.3 or later with SQLite and the built-in development server. You do not need Apache, Nginx, IIS, Redis, Composer, npm, or an external database server to try PBreeze.

    For production, choose Apache with FastCGI/PHP-FPM, Nginx with PHP-FPM, FrankenPHP standard mode, or IIS FastCGI. Follow the Web Server Deployment chapter after completing the common setup below. Subdirectory hosting and persistent FrankenPHP workers are outside the supplied deployment scope.

    Use a new empty directory for a fresh installation. These instructions are not an upgrade procedure: do not overwrite an existing application's .env, encryption key, database, uploads, or private storage.

    2. Install PHP on Linux

    On a Debian/Ubuntu installation whose configured repositories provide PHP 8.3 or later, the following installs the usual local-development requirements:

    sudo apt-get update
sudo apt-get install php-cli php-sqlite3 php-intl php-mbstring php-xml php-zip php-curl
php -v
php --ini
php -m

    Confirm the reported PHP version is at least 8.3. Distribution defaults vary: if your repositories provide an older release, use a supported distribution/repository that provides a compatible PHP version. Do not mix extension packages from different PHP release series.

    Some PHP builds bundle OpenSSL, iconv, JSON, session, filter, and fileinfo; others package them separately. Verify actual modules rather than assuming the package command is sufficient. On other Linux distributions, install equivalent packages through that distribution's supported package manager. For FPM deployment, additionally install the matching php-fpm package (often versioned, such as php8.3-fpm) and configure it with your server. The development server needs only CLI PHP.

    Check the extensions used by the bundled features and native tests:

    php -r 'foreach (["PDO","pdo_sqlite","openssl","session","json","filter","intl","mbstring","fileinfo","curl","iconv","zip","dom"] as $e) { echo $e, ": ", extension_loaded($e) ? "OK" : "MISSING", PHP_EOL; }'

    Install/enable any missing extension for the PHP binary shown by php -v. The native test runner also needs proc_open and local socket functions. If a hosting policy disables them, run the tests on an appropriate development/CI machine; do not blindly weaken a production hosting policy.

    3. Install PHP on Windows

    1. Download a supported PHP 8.3+ Windows ZIP build from https://windows.php.net/download/. Use the architecture matching your system and server. An NTS build is appropriate for CLI development and IIS/FastCGI; Apache module installations require the matching TS/module combination instead. Follow the PHP build's Visual C++ runtime requirements.
    2. Extract PHP to a directory such as C:\PHP. Copy php.ini-development to php.ini for local work; use a reviewed production configuration for deployed services.
    3. Set extension_dir = "C:/PHP/ext" in that INI file. Enable the available extension lines below by removing their leading semicolon:
    extension=pdo_sqlite
extension=sqlite3
extension=openssl
extension=intl
extension=mbstring
extension=fileinfo
extension=curl
extension=zip

    DOM, iconv, JSON, session, filter, and PDO may already be compiled into your build. Verify with php -m; do not add DLL lines for extensions already built in or install DLLs from an incompatible PHP version, architecture, or thread-safety build.

    1. Add C:\PHP to your user/system PATH using Windows Environment Variables, then open a new PowerShell or Command Prompt window.
    2. In PowerShell, verify the executable and loaded configuration:
    Get-Command php
php -v
php --ini
php -m

    If PHP is not on PATH, run & "C:\PHP\php.exe" -v and use the same explicit executable for the remaining commands. Resolve startup warnings such as “Unable to load dynamic library” before proceeding. No WSL, Bash, or executable permission on the breeze file is required.

    4. Obtain the framework files

    Download and extract the project's source archive, or clone the actual repository URL supplied by your project maintainer. PBreeze does not require composer install, autoload generation, or an npm build.

    Use a private working directory such as ~/projects/pbreeze on Linux or C:\Projects\PBreeze on Windows. Do not extract the project directly into a public web root. The full source must include breeze, bootstrap.php, .env.example, framework/, app/, config/, routes/, database/, and public/; enable “show hidden files” when checking archive contents.

    Open a terminal inside the project directory:

    cd /absolute/path/to/pbreeze
php breeze help

    PowerShell equivalent:

    Set-Location "C:\Projects\PBreeze"
php breeze help

    If your source directory has spaces, quote the path. Do not point commands at another installed copy accidentally. Existing process environment variables override .env; unexpected settings may come from your shell or service definition.

    5. Initialize local configuration

    php breeze init

    This copies .env.example only when .env does not already exist. Open the new .env privately in your editor. For the SQLite/local-development path, verify these values:

    APP_ENV=local
APP_DEBUG=false
APP_URL=http://127.0.0.1:8000
SESSION_SECURE_COOKIE=false
DB_CONNECTION=sqlite

    Leave cache, AI, SMTP, and IMAP credentials empty until you intentionally configure those services. The environment file supports NAME=value, optional matching quotes, and full-line comments; it does not expand shell variables or support inline comments. Keep it out of version control and never paste its contents into tickets or public logs.

    Generate an encryption key:

    php breeze key:generate

    Copy the printed APP_KEY=base64:... assignment into your private .env. The command prints only and does not update the file. Do not publish the output. Keep a separate protected backup; replacing the key later does not re-encrypt existing records and can make encrypted data unrecoverable. On an existing application, preserve its original key.

    6. Prepare storage and the database

    For a fresh local SQLite installation:

    php breeze storage:prepare
php breeze migrate
php breeze migrate:status
php breeze db:seed

    storage:prepare creates private logs, uploads, and compiled-view directories. migrate creates/applies the bundled schema in the configured SQLite file. migrate:status should show applied batch numbers rather than OPEN. The optional default seeder adds a welcome note; it does not create an administrator or a preconfigured login.

    Run these commands as the identity that should own local application data. On Linux, newly created private files may be readable only by their owner. On Windows, configure NTFS ACLs explicitly; chmod is not equivalent. Do not solve permission errors with chmod 777, administrator-owned application data, or write access to the entire deployed source tree.

    php breeze about
php breeze env:check
php breeze test
php breeze serve

    about reports CLI runtime/driver information without credentials. env:check inventories environment key names without printing values; empty unused integration settings are expected. The native tests use isolated fixtures, not your configured application database, and send no external email or AI requests. Optional live database/cache/server integration tests are separate and have their own prerequisites.

    Open http://127.0.0.1:8000. Confirm that the home page and its CSS load. Check http://127.0.0.1:8000/health for liveness and http://127.0.0.1:8000/ready for database/schema/private-storage readiness. Both should return HTTP 200 after successful setup; /ready returns 503 when its dependencies are not ready.

    Stop the development server with Ctrl+C. If port 8000 is occupied, use php breeze serve 8080 and update APP_URL to http://127.0.0.1:8080 before testing links generated by the application. Never use php breeze serve as the production web server.

    8. Enable optional integrations deliberately

    • Authentication emails: configure a real MAIL_FROM and encrypted SMTP host/port/login. Registration verification and password recovery require delivery; a page loading successfully does not prove mail works. Schedule php breeze mail:work 50 using cron or Windows Task Scheduler. Test delivery only to an authorized address; IMAP is optional.
    • Redis/Memcached: install the selected native extension in CLI and web PHP, configure a protected server and a unique CACHE_PREFIX, then run php breeze cache:test. This deliberately writes/reads/deletes one temporary key. Keep CACHE_DRIVER=none when no cache is configured.
    • OpenAI/Claude: configure the selected provider's API key and exact model ID, plus native cURL/system trust. API usage can incur charges; framework tests do not make real provider requests.
    • Document generation/uploads: verify ZIP, DOM, iconv, fileinfo, PHP upload limits, and writable private storage. Application upload limits cannot raise PHP or web-server limits.

    Refer to each integration's chapter before enabling it in production.

    9. Move to a production web server

    1. Back up the database, private data, and encryption key. Configure a real HTTPS origin, production credentials, and stable private storage outside public/; keep its real path free of symlink ancestors.
    2. Set APP_ENV=production, APP_DEBUG=false, and the HTTPS APP_URL. Set secure cookies and configure actual HTTPS at the server/trusted edge. Restrict public API docs if not intended for public access.
    3. Follow the Apache, Nginx, FrankenPHP, or IIS instructions in Web Server Deployment. Expose **only public/**. Configure the actual web PHP INI/extensions, service identity, sessions, upload temporary directory, timeouts, certificates, and permissions.
    4. Under the deployment identity, run php breeze storage:prepare and review php breeze migrate:status. After a verified backup and schema review, production migration execution requires php breeze migrate --force. Do not automatically run development seeders against production.
    5. Run php breeze doctor. Resolve failures and review every warning. A local installation normally fails production-only checks; that is not evidence that local development is broken.
    6. Smoke-test real HTTPS routes, assets, sessions/login, authorized API requests, uploads, mail delivery, /health, and /ready. Test backups, restores, monitoring, scheduled mail, and expected load before release.

    CLI checks do not certify another PHP SAPI or a complete deployment. The production and server chapters explain remaining operational boundaries.

    Windows and Linux

    Use the same commands on both systems with php breeze .... On Windows, this works from PowerShell or cmd, without WSL, Bash, or an executable shebang. Make sure PHP CLI is in PATH; check with php -v and use php --ini to find the configuration file in use. PHP for your web server may use a different configuration file.

    On Windows, enable the required extensions in php.ini: pdo_sqlite for SQLite, pdo_mysql for MySQL, pdo_pgsql for PostgreSQL, or pdo_sqlsrv for SQL Server, and also openssl and iconv for email. Enable zip for Excel/Word creation and dom for the document tests. Enable intl for localized date/time and number formatting. Enable fileinfo for upload validation. Use the correct DLLs for your PHP distribution. OpenSSL requires a valid CA bundle; set openssl.cafile if needed or use the separate SMTP_CA_FILE/IMAP_CA_FILE settings.     Relative database paths are always relative to the project root. Both database/app.sqlite and database\app.sqlite are allowed. Full Windows drive paths and UNC paths are recognized, for example:

    DB_DATABASE="C:/Data/PBreeze/app.sqlite"

    Backslashes are also allowed and are not treated as .env escapes. Do not use drive-relative paths such as C:app.sqlite. Give the service user write access only where needed. On Windows, tests check read/write access, not Unix permission bits.

Always set the document root to public/; see Web Server Deployment for exact requirements, configuration, and validation boundaries.

    The .github/workflows/tests.yml workflow runs the full native suite on ubuntu-latest and windows-latest, with PHP 8.3 and 8.5, once the project is on GitHub and Actions is enabled. Adding a workflow does not mean a Windows test has been run.

    Runtime and environment diagnostics

    about prints safe runtime metadata: PHP version, OS family, SAPI, environment, configured database/cache driver names, session handler, and loaded extensions. The framework has no declared release version yet, so the command says so instead of inventing one. It does not print credentials, application keys, connection strings, or filesystem paths, and does not connect to services or create storage. CLI information does not certify the web server's PHP extensions or configuration.

    env:check compares your local .env key names against .env.example, honoring process environment overrides without changing files or loaded configuration. Output contains names and statuses only, never values:

    StatusMeaning
    SETAn effective value is present and nonempty
    EMPTYExplicitly empty; may be intentional for unused integrations
    MISSINGAn active example setting has no file/process value
    OPTIONALA commented example setting has no override
    CUSTOMA local file key is not listed in the example

    Exit code is 1 if active example keys are missing, otherwise 0. Missing keys can still have framework defaults; this is a configuration inventory check, not a production certification. Empty, optional, and custom entries need human review, not automatic replacement. Duplicate/malformed local entries fail explicitly without printing their contents. All CLI commands still require bootstrap to succeed: invalid typed configuration can prevent this command from starting. Use doctor for production settings/readiness.

    Testing cache connectivity

    cache:test checks the selected configured backend using one cryptographically random key in its existing namespace. It writes with a 30-second TTL, verifies the round trip, and deletes only its probe key. It never flushes the server or changes other application keys. Disabled/missing/unreachable backends fail explicitly; there is no fallback. Cleanup is attempted after a successful write; interrupted or uncertain writes expire automatically. Success output contains no key, value, host, or credentials. Native backend failures use the cache service's redacted errors and normal CLI error logging.

    Reading recent application logs

    logs:tail [lines] [level] is a one-shot snapshot, not a continuous watcher. It prints the most recent matching entries in chronological order, across the configured storage directory's daily JSONL files. The line count is 1..1000, default 50. The optional second argument is the minimum severity: debug, info, notice, warning, error, critical, alert, or emergency; default debug includes every level.

    Reading does not create storage, write log files, or trigger retention. Missing logs produce a clear informational message. Symlinked paths, corrupt JSON/levels, entries above 64 KiB, and scans exceeding 8 MiB fail explicitly; request fewer lines or a less restrictive filter for large logs. JSON output escapes terminal control characters. Existing log messages and context may still contain private application data: logger key-based redaction does not sanitize arbitrary message text. Restrict terminal/log access and never paste confidential output into public systems.

    Creating application-specific commands

    make:command Report creates app/commands/Report.php containing a Closure. The generated command deliberately throws until implemented, preventing an empty success-shaped scaffold. Existing files are never overwritten. Implement it, then register it explicitly in routes/console.php:

    <?php
declare(strict_types=1);

return [
    'app:report' => require $app->root . '/app/commands/Report.php',
];

    For example, the command file can return:

    <?php
declare(strict_types=1);

use PBreeze\Application;

return static function (Application $app, array $arguments): int {
    if ($arguments !== []) {
        throw new InvalidArgumentException('Usage: php breeze app:report');
    }
    echo "Report completed.\n";
    return 0;
};

    Run php breeze app:report. Help lists registered custom names. The registry is optional for older projects; create it with the structure above. There is no Composer, autoloading, or command-directory scanning. Names must match lowercase letter-led segments containing letters, digits, or hyphens, optionally separated by colons. Builtin names cannot be overridden; every entry must be a Closure.

    Handlers receive the Application and unchanged remaining CLI arguments, including any options. They must validate their arguments themselves and return an integer exit code from 0 through 255. Exceptions use the existing CLI error path. Custom commands must implement their own production guards, authorization, confirmation, and secret handling; builtin --force safeguards do not automatically apply to arbitrary custom code. The five utility commands above do not accept --force or other options.

    Shared deployment contract

    1. The document root/physical site path must be **only public/**. Never expose the project root, even if a rewrite rule appears to hide it.

    4. Preserve the original URI/query string, method, raw request body, Authorization header, status code, response body, and Allow header. Do not replace framework JSON 4xx/5xx errors with HTML error pages.
    5. Install the same required PHP extensions in the web runtime as in CLI. FrankenPHP has its own embedded PHP/extensions/INI configuration; a successful php -m for CLI does not prove its extensions are available.
    6. Configure writable private storage, persistent SQLite/database access, PHP session storage, and upload temporary storage for the actual service identity. Keep application source read-only. Run storage:prepare and migrations with a compatible deployment identity; run php breeze doctor.
    7. Terminate HTTPS at the server or a trusted edge. Set APP_ENV=production, APP_DEBUG=false, and the real HTTPS APP_URL. Set SESSION_SECURE_COOKIE=true behind TLS termination; the flag does not encrypt HTTP or validate proxy identity. Never trust arbitrary forwarded headers. Restore client IPs only using an allowlisted proxy configuration.

Configure PHP post_max_size=8M, upload_max_filesize=3M (or values appropriate to your application), a writable upload_tmp_dir, and persistent session.save_path. Coordinate execution/FastCGI/proxy timeouts with long AI operations, and disable response buffering where your application requires streaming.     Redis and Memcached Cache

    The shared $app->cache service supports Redis and Memcached using native PHP extensions, without Composer. It is optional and disabled by default. It does not replace PHP sessions, database-backed rate limits, the mail queue, or the compiled-template cache.

    Enable the matching extension in both CLI and web PHP. For example, on Linux install your PHP distribution's redis or memcached extension package. On Windows, use a compatible extension build matching your PHP version, architecture, and thread-safety mode; enable it in the appropriate php.ini. The modern memcached extension is used, not the legacy memcache extension. Verify with php --ri redis or php --ri memcached. A separate Redis or Memcached server is required; it may run on another private host.

    Cache configuration

    Choose one backend in your private .env:

    CACHE_DRIVER=redis
CACHE_PREFIX=myapp-production:
CACHE_TIMEOUT=2
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_DATABASE=0
REDIS_TLS=false

    For Memcached, use CACHE_DRIVER=memcached, MEMCACHED_HOST=127.0.0.1, and MEMCACHED_PORT=11211. Set CACHE_DRIVER=none to disable caching explicitly. Disabled or unavailable caching throws when used: it never pretends that a failed operation is a miss or silently switches to local memory. Construction and normal bootstrap do not connect to either server. There is no application-level automatic retry.

    Use a unique CACHE_PREFIX per application and environment (1..64 ASCII letters, digits, :, _, or -). Keys are stored as the prefix plus a SHA-256 hash, keeping backend keys bounded and separating namespaces. Prefixes and hashes are not authorization or encryption. Never share cache write access with untrusted applications.

    Redis supports password-only authentication with REDIS_PASSWORD, or ACL authentication with both REDIS_USERNAME and REDIS_PASSWORD. Set REDIS_TLS=true for verified TLS; REDIS_CA_FILE optionally selects a trusted CA bundle, otherwise system trust applies. The certificate must match REDIS_HOST; certificate and hostname verification cannot be disabled. Redis ACLs must permit GET, SET, SETEX, DEL, SELECT, EVAL, INCRBY, and EXPIRE. This is a single-server adapter, not a Redis Cluster/Sentinel client.

    Memcached supports optional SASL through MEMCACHED_USERNAME and MEMCACHED_PASSWORD (both required together), with a SASL-capable extension and server. It uses binary protocol. SASL is authentication, not encryption: this adapter does not provide Memcached TLS. Use a protected private network or a separately secured tunnel; never expose Memcached publicly. Plaintext Redis is likewise appropriate only on a trusted network. Do not put credentials in controllers, logs, or version control.

    Cache values, expiration, and remembered results

    $app->cache->set('catalog:featured', ['id' => 42, 'name' => 'Notebook'], 600);
$featured = $app->cache->get('catalog:featured', []); // Default only on a miss.
$removed = $app->cache->delete('catalog:featured');  // false if already absent.

$app->cache->set('feature:enabled', false, 60);
$enabled = $app->cache->get('feature:enabled', true); // false, not the default.
$app->cache->set('optional:value', null, 60);        // null is cacheable too.

$notes = $app->cache->remember('notes:recent', function () use ($app): array {
    return $app->db->table('notes')->orderBy('id', 'desc')->limit(10)->get();
}, 120);

    set(), remember(), and increment() default to 300 seconds. TTL is a relative integer number of seconds, 0..31536000 (one year); 0 means no expiration, not deletion. Values may still be evicted by the server. Memcached's special absolute-timestamp behavior above 30 days is normalized automatically. get() defaults to null on a genuine missing/expired key. delete() returns whether an entry was removed and never flushes the server. There is intentionally no whole-server clear operation.

    Values support null, booleans, integers, finite floats, valid UTF-8 strings, and nested arrays. PHP objects (including models and dates), resources, recursive arrays, and invalid UTF-8 are rejected. Convert models to arrays before caching them. JSON encoding is limited to 512 KiB per value and 60 nested array levels; no PHP object serialization is written by this service. Only use trusted cache servers; data retrieved from a cache is not an authorization decision and must still be escaped for HTML output.

    remember() runs the callback only on a miss, including when a previously cached value is null or false. Callback exceptions propagate unchanged and are not cached. Concurrent misses may run the producer more than once: this helper is not a distributed lock or stampede-prevention mechanism. Backend/extension/protocol failures throw RuntimeException, rather than returning a default or calling the producer. Invalid API inputs throw InvalidArgumentException. Native errors are redacted; uncaught exceptions use the framework's existing web/CLI error handling and logging.

    Atomic cache counters

    $views = $app->cache->increment('article:42:views', 1, 3600);
$views = $app->cache->increment('article:42:views', 5); // Add five.

    A missing counter starts at the positive amount (default 1). Existing counters must contain nonnegative integers; integer values written by set() can be incremented, but numeric strings cannot. Creation/expiration and increments are atomic. TTL applies only when creating the counter; increments preserve the existing expiry. Redis requires Lua/EVAL permission for this. Keep counters within PHP_INT_MAX. Redis rejects signed-64-bit overflow; Memcached uses native unsigned-64-bit arithmetic, which can wrap at its limit. Values outside PHP's integer range cause an exception, potentially after Memcached has changed the counter. These evictable counters are not durable financial records, distributed locks, or a replacement for the framework's existing authentication/API rate limits.

    AI: Claude and OpenAI

    The server-side $app->ai service supports text conversations and incremental text streaming through OpenAI's Responses API and Anthropic's Claude Messages API. It uses native PHP cURL, not an SDK or Composer. It does not create public routes or a chat UI. ChatGPT/Claude subscriptions do not provide API credentials or include API usage; obtain a provider API key and enable billing/access separately.

    Configuration

    Add these settings to your existing .env or process environment. Set only the providers you use; never commit real API keys:

    AI_PROVIDER=openai
AI_TIMEOUT=60
AI_MAX_TOKENS=1024
AI_CA_FILE=
OPENAI_API_KEY=
OPENAI_MODEL=
ANTHROPIC_API_KEY=
ANTHROPIC_MODEL=

    AI_PROVIDER accepts openai or anthropic (Claude). Set the API key and exact API model ID available to that account, not a ChatGPT/Claude UI label. Model settings are intentionally empty: no possibly retired model is silently chosen. Provider construction makes no network requests and permits unconfigured providers; calling an unconfigured provider fails explicitly.

    AI_TIMEOUT is the complete request deadline in seconds (1..300), including streaming. Connection setup is capped at the smaller of 15 seconds and that deadline. AI_MAX_TOKENS is the default output budget (1..128000); each model may enforce lower limits. Some reasoning models use output tokens internally, leaving fewer visible text tokens. AI_CA_FILE optionally specifies a readable CA bundle; otherwise native cURL/system trust and curl.cainfo apply. Keep certificate verification enabled and configure the correct CA store on both Windows and Linux.

    Bootstrap reads config/ai.php and exposes $app->ai. Programmatic application configuration can supply ai with provider, integer timeout/max_tokens, ca_file, and openai/anthropic arrays containing key and model. API keys and models are validated only for the provider used by each call.

    Text conversations

    $app = require __DIR__ . '/bootstrap.php';

$reply = $app->ai->chat(
    [['role' => 'user', 'content' => 'Explain PHP routing in two sentences.']],
    provider: 'anthropic',
    system: 'Be concise and use US English.',
    maxTokens: 512,
);

echo $reply['text']; // Plain-text CLI output. Escape with e() in HTML.

    Omit provider to use AI_PROVIDER. Optional model and maxTokens named arguments override configuration for one call only. system is a separate trusted instruction string, not an entry with role system.

    Pass a nonempty list of messages containing exactly role (user or assistant) and nonempty UTF-8 content. The caller owns conversation history:

    $messages = [['role' => 'user', 'content' => 'What is CSRF?']];
$first = $app->ai->chat($messages, provider: 'openai');
$messages[] = ['role' => 'assistant', 'content' => $first['text']];
$messages[] = ['role' => 'user', 'content' => 'Give a short PHP example.'];
$second = $app->ai->chat($messages, provider: 'openai');

    Every successful call returns exactly:

    KeyMeaning
    provideropenai or anthropic
    idProvider response/message ID
    modelModel ID reported by the provider
    textCombined visible text, including an OpenAI text refusal when returned
    finish_reasonExplicit provider completion reason; inspect before treating text as complete
    input_tokensProvider-reported nonnegative input-token counter
    output_tokensProvider-reported nonnegative output-token counter

    OpenAI normally reports completed; text refusals report refusal. A token-budget-limited OpenAI response reports max_output_tokens. Claude normally reports end_turn, with possible max_tokens, stop_sequence, refusal, or model_context_window_exceeded. Token/context-limit results contain partial text: inspect the reason and decide whether to request more. Empty visible text, provider failures, and unsupported non-text results throw rather than returning a success-shaped empty answer. Token counters are not a cost estimate and do not include separately reported cache counters or pricing calculations.

    Streaming text

    $reply = $app->ai->stream(
    [['role' => 'user', 'content' => 'Explain prepared statements briefly.']],
    static function (string $delta): void {
        echo $delta; // Plain-text CLI output, not HTML.
    },
    provider: 'openai',
    system: 'Use plain text.',
);

// $reply contains the same metadata and complete assembled text as chat().

    The callback runs synchronously for each nonempty text delta as it arrives, not after the whole response has been buffered. The method returns only after a valid terminal event and complete HTTP transfer. SSE comments, fragmented UTF-8/network chunks, LF/CRLF/CR framing, and multiline data fields are handled. If your callback throws, the connection is canceled and that exception propagates.

    Partial output is not proof of success. An HTTP interruption, timeout, provider stream error, malformed event, missing terminal event, or mismatched OpenAI final text throws even when the callback has already received text. Do not automatically retry streams, and do not persist a partial answer as complete. There are no automatic retries or provider fallback, avoiding duplicate output and unexpected charges.

    This callback API is not an HTTP SSE endpoint. Application code must explicitly authenticate/authorize any endpoint it adds, impose rate limits and spending budgets, choose framing/content types, and configure proxy/output buffering and PHP execution timeouts. Close an active PHP session with session_write_close() before a long-running web stream if it no longer needs session changes.

    Errors, limits, and privacy

    Invalid caller input or missing selected-provider configuration throws InvalidArgumentException. HTTP, network/TLS, provider, JSON, unsupported-content, and premature-stream failures throw RuntimeException. Non-200 HTTP errors include their status in $error->getCode() (for example 401 or 429) but never copy raw provider error bodies or credentials into the exception message. Catch errors at the application boundary and show a generic failure; inspect only safe metadata in private diagnostics. Callback exceptions remain unchanged.

    The native client uses fixed HTTPS provider URLs, verifies TLS certificates and hostnames, never follows redirects, and enforces a total timeout. Requests are capped at 4 MiB; responses at 16 MiB including stream metadata; each SSE event at 4 MiB. Provider token/context limits still apply. The framework does not store or log keys, prompts, responses, or conversation history. OpenAI requests set store=false, which is not a guarantee of zero provider retention: check each provider's data policies before sending personal or confidential content.

    AI output is untrusted. Escape it in HTML, never execute generated code or SQL automatically, and do not let prompts grant authorization. Keep API keys out of browser scripts, templates, logs, and source control. This API supports only text input/output; images, tools/function calls, structured output, audio, provider-side conversation persistence, and full reasoning-state replay are not implemented.

    For isolated tests, new \PBreeze\Ai($config, $transport) accepts an optional trusted transport Closure with signature function (string $url, array $headers, string $json, int $timeout, \Closure $receive): void. It must synchronously pass successful response-body chunks to $receive and throw for network errors or non-200 HTTP responses. The replacement controls its own TLS, HTTP status, and timeout safeguards; never derive it from request input. Normal applications should use the built-in transport.

    Provider protocols: OpenAI Responses API, OpenAI streaming, Claude Messages API, Claude streaming.

    Form Generator

    Create a standalone Breeze form view using field:type arguments:

    php breeze make:form forms.contact name:text email:email message:textarea

    This writes app/views/forms/contact.breeze.php. Names use the same dot-separated format as other view generators; fields use lowercase snake_case names beginning with a letter. At least one field is required and duplicate fields are rejected. Supported types: text, email, password, textarea, number, date, time, datetime-local, url, tel, and checkbox. Selects and file uploads are not generated; add those controls manually when needed.

    The generated POST form includes @csrf($session), associated labels, and escaped previous values. Field errors use aria-invalid and aria-describedby. Passwords are never repopulated; their autocomplete defaults to new-password (change it to current-password for a login form). Checkboxes submit 1 when checked and submit nothing when unchecked; previous values 1, '1', or true restore the checked state. Array-valued old input is not inserted into controls. Fields are optional by default: add required, lengths, limits, and other HTML attributes to suit your form, and always validate on the server.

    Render the form with a Session and a trusted local action URL. Optional old values are an array keyed by field name; errors has the array<string, list<string>> shape returned by Validator::errors():

    // Inside a controller action; register the GET/POST routes explicitly yourself.
$input = $request->method === 'POST' ? $request->all() : [];
$errors = $request->method === 'POST'
    ? \PBreeze\Validator::errors($input, [
        'name' => 'required|string|max:80',
        'email' => 'required|email|max:254',
        'message' => 'required|string|max:2000',
    ])
    : [];

// Handle a valid POST here, then redirect; this example only renders the view.
return new \PBreeze\Response($this->app->views->render('forms.contact', [
    'session' => $this->app->session,
    'action' => '/contact',
    'old' => array_intersect_key($input, array_flip(['name', 'email', 'message'])),
    'errors' => $errors,
]), $errors === [] ? 200 : 422);

    Only the form markup is generated, not a layout, controller, route, validation rules, authorization, bot protection, or data storage. Include it in a page with @include('forms.contact'), or add your own layout. Include a particular form only once per page so its generated label/error IDs remain unique. Do not retain passwords or other secrets in old, logs, or sessions.

    Existing .php and .breeze.php views are preserved. The command rejects --force rather than overwriting them.

    Application Logging

    Use the native $app->log service for structured application logs. No Composer, PSR interface, database migration, or external logging package is required.

    $app->log->info('Report created.', ['report_id' => 42]);
$app->log->warning('Delivery delayed.', ['attempt' => 2]);
$app->log->error('Processing failed.', ['exception' => $exception]);
$app->log->log('notice', 'Import completed.', ['rows' => 120]);

    Available methods/levels, from lowest to highest severity, are debug, info, notice, warning, error, critical, alert, and emergency. Configure the minimum level and retention in .env:

    LOG_LEVEL=debug
LOG_RETENTION_DAYS=5

    The corresponding application configuration keys are log_level and log_retention_days. Retention must be an integer from 1 through 3650. Levels are lowercase and validated when the application is constructed. Standalone usage is also supported:

    $logger = new \PBreeze\Logger($app->root, retentionDays: 5, minimumLevel: 'info');
$logger->notice('Maintenance completed.');

    Logs are newline-delimited JSON in storage/logs/app-YYYY-MM-DD.jsonl. Each entry contains a UTC ISO-style timestamp with microseconds, level, message, and context. Embedded line breaks are JSON-escaped; a message cannot inject a second log record. Directories are created lazily with 0700 and files/locks use 0600 on Linux. On Windows, restrict inherited NTFS ACLs to the administrator and PHP service user. Storage stays outside public/, rejects symlinked directories/files, and is ignored by the existing Git rules. Never expose the storage directory through a web-server alias.

    Concurrent writers serialize through a private file lock. After each written entry, retention removes only matching daily log files older than the retained UTC calendar window: five days means today plus the previous four dates. Unrelated files and symlinks are not removed. Cleanup runs on writes, not on a background schedule; filtered entries do not trigger cleanup. Files are daily, not size-rotated: provision disk space, choose an appropriate minimum level, and monitor write failures.

    Context supports nested arrays, scalars, null, and exceptions. Sensitive keys containing password, secret, token, authorization, cookie, credential, or API/ private-key names are recursively replaced with [REDACTED]. Exceptions are reduced to class, source file, and line; exception messages, traces, previous exceptions, and arguments are deliberately omitted because they may contain credentials or request data. Context is limited to eight nested levels and each serialized entry to 64 KiB. Unsupported objects/resources, invalid UTF-8, nonfinite numbers, recursive/deep context, or oversized entries throw explicitly. Messages are plain text; there is no placeholder interpolation.

    Redaction is not a general secret detector. It does not inspect arbitrary message text or values under unrelated keys. Do not log passwords, tokens, connection strings, full request objects, uploaded contents, or personal data. Choose safe, minimal context fields explicitly.

    Unexpected web/API errors are logged automatically through the configured application logger while existing public error responses remain unchanged. Server-side HTTP exceptions (5xx) are also logged; ordinary validation, authentication, and other 4xx responses are not. API errors caught inside the API router use the same logger. CLI command failures after application startup are logged except invalid-argument/usage errors. There is no automatic access log or request-body/header/query logging.

    Direct logger writes throw on failure. Automatic exception reporting catches logging failures and explicitly reports a safe diagnostic to PHP's server log without recursively invoking the file logger. Errors before application initialization also use the PHP server log; the CLI still prints its error and exits with a failure status. This service does not install global error/exception handlers or capture engine fatal errors/shutdown events: keep PHP's log_errors and server monitoring configured. A minimum level above error also filters automatic application-error entries.

    File Uploads

    Web routes accept native PHP multipart/form-data uploads through Request. Use an explicit list of allowed filename extensions for each upload handler. There is deliberately no allow-all default. The default per-file size limit is 2 MiB (2,097,152 bytes).

    Configure the application default in .env:

    UPLOAD_MAX_BYTES=2097152

    This must be a positive integer number of bytes. It configures $app->uploads->maxBytes through upload_max_bytes in the application config. It does not change PHP's upload_max_filesize or post_max_size.

    Supported types are jpg, jpeg, png, gif, webp, pdf, txt, csv, docx, and xlsx. Use lowercase extensions without a dot. Uploaded extension matching is case-insensitive. PHP/script files, HTML, SVG, arbitrary ZIP archives, and legacy .doc/.xls files are not supported.

    Receiving and Storing a File

    Register a protected web route in routes/web.php:

    use PBreeze\HttpException;
use PBreeze\Request;
use PBreeze\Response;

$router->post('/documents', $app->auth->protect(
    static function (Request $request) use ($app): Response {
        $file = $request->file('document');
        if ($file === null) {
            throw new HttpException(422, 'Choose a document to upload.');
        }
        $stored = $app->uploads->store(
            $file,
            allowedTypes: ['pdf', 'docx', 'xlsx'],
        );

        // Persist these values with the current user's ID in your own model.
        // Delete the stored upload if your database write subsequently fails.
        return Response::json([
            'key' => $stored->key,
            'name' => $stored->originalName,
            'mime' => $stored->mimeType,
            'size' => $stored->size,
        ], 201);
    },
));

    In a Breeze template, submit a multipart form with the normal CSRF field. Pass 'session' => $app->session in the view's render data:

    <form action="/documents" method="post" enctype="multipart/form-data">
    @csrf($session)
    <label for="document">Document</label>
    <input id="document" name="document" type="file" accept=".pdf,.docx,.xlsx" required>
    <button type="submit">Upload document</button>
</form>

    The browser's accept attribute is only a selection hint, not validation. JavaScript clients may send the CSRF token in X-CSRF-Token; let the browser set the multipart boundary when using FormData.

    file() returns an UploadedFile or null for a missing field/no file selection. If more than one file is supplied to a single-file accessor, it throws HTTP 400. files() always returns a list; missing selections are omitted. One-dimensional documents[] and keyed file lists are supported; deeper nested upload fields are rejected with HTTP 400. Nonempty PHP upload failures remain accessible and are reported by validation.

    The uploaded object exposes originalName, clientMediaType, and PHP's error code. Client path components are removed from the original name; the remaining UTF-8 name must contain 1 to 255 bytes without control characters. Treat this name as display metadata and escape it in HTML. The client media type is explicitly untrusted and is never used to approve or serve a file.

    store() validates before writing. It returns a StoredUpload with read-only key, originalName, mimeType, and actual byte size properties. It uses is_uploaded_file() and move_uploaded_file(): arbitrary local server files and CLI-created temporary files cannot be passed off as uploads. Each file receives a cryptographically random 64-hex-character key plus its validated extension. Files are stored as storage/uploads/<random-id>/file.<extension>, never under the client's name, so equal original names cannot overwrite one another.

    Storage directories are created on demand with 0700 permissions and files receive 0600 on Linux. On Windows, restrict inherited NTFS ACLs to the administrator and PHP service user. The storage location is outside public/; symlinked storage directories and symlinked stored files are rejected. Upload contents are ignored by the existing storage/ Git ignore rule.

    There is no automatic attachment database table or ownership model. Persist the storage key, display name, size, media type, and owner as your application requires. Keys locate files; they are not authorization credentials. No public upload/download routes are installed by this feature.

    Multiple Files and Custom Limits

    $files = $request->files('documents');
if ($files === [] || count($files) > 5) {
    throw new \PBreeze\HttpException(422, 'Choose between one and five files.');
}

// Check every file before starting a batch write.
foreach ($files as $file) {
    $metadata = $app->uploads->validate($file, ['jpg', 'jpeg', 'png'], maxBytes: 524288);
}
foreach ($files as $file) {
    $stored = $app->uploads->store($file, ['jpg', 'jpeg', 'png'], maxBytes: 524288);
    // Persist each file and its owner.
}

    Use an input with name="documents[]" and the multiple attribute. $app->uploads->validate($file, $allowedTypes) performs the same checks as store() without moving the file, using the configured default, returning extension, canonical mime, and actual byte size. The optional positive integer maxBytes overrides the configured per-file default; it does not raise PHP or web-server limits. Empty files are rejected. Calling $file->validate() directly is standalone validation and retains a 2 MiB default unless you explicitly pass maxBytes; use the application service for environment-aware validation.

    Batches are not filesystem/database transactions. Prevalidating a batch avoids starting writes for an already-invalid file, but disk or database failures can still occur later. Track successful keys and clean them up if the operation must be all-or-nothing. Enforce application-specific file-count, combined-byte, user-quota, and rate limits.

    Protected Downloads and Deletion

    After authenticating a user and loading an attachment record belonging to that user, return:

    return $app->uploads->download($attachment['storage_key'], $attachment['original_name']);

    Register the download action with $app->auth->protect(...) and perform the ownership/record authorization check before calling download(). Never authorize access just because someone knows a random storage key. download() itself is a storage operation, not an authorization service. Its optional filename defaults to download.<extension>; the original name must come from your persisted metadata if you want to restore it.

    Downloads reuse the normal attachment response: canonical media type, UTF-8-safe filename headers, correct byte length, nosniff, and no-store. HEAD requests omit the response body. Invalid keys, missing files, and symlinked file targets produce HTTP 404. Files are read into memory to build the response; bound upload limits accordingly.

    After the same authentication and ownership checks, a CSRF-protected POST or DELETE handler may call:

    $app->uploads->delete($attachment['storage_key']);

    This removes only that stored file and its random directory. Coordinate deletion of your database metadata explicitly; deleting an attachment record does not automatically delete the file, and deleting a file does not update your database.

    Validation and Deployment Limits

    • Validation checks the real temporary file size, allowed extension, and server-detected media type using native fileinfo, not client-provided size/type claims.
    • Images also undergo a native header/dimension check. This is not a full image decode, re-encoding service, or pixel-count limit; add application image-dimension limits before further processing untrusted images.
    • DOCX/XLSX files must be ZIP packages containing the matching main document, content-type, and relationship entries. Checks reject macro-named entries, encrypted entries, unsafe archive paths, more than 1,000 entries, entries larger than 10 MiB, or a combined declared expansion larger than 20 MiB. Archives are not extracted. These are bounded package-shape checks, not complete Office schema validation or a guarantee of harmless content.
    • MIME/header checks are not malware scanning or content sanitization. PDFs and Office documents may contain active content or external links. Uploaded CSV files may contain spreadsheet formulas; validation does not rewrite their contents. Add quarantine/scanning if your deployment requires it. Do not execute, include, extract, or render uploaded content inline simply because it passed validation.
    • file_uploads must be enabled. Configure a writable PHP upload_tmp_dir and writable private storage. Enable native fileinfo; Office checks additionally need zip.
    • PHP's upload_max_filesize must accommodate the per-file limit; post_max_size must accommodate all files, form fields, and multipart overhead. For a single 2 MiB file, a typical starting point is upload_max_filesize=2M and post_max_size=8M. Configure these in the PHP configuration used by your actual web server.
    • PHP's max_file_uploads, max_input_vars, and max_input_nesting_level can limit parsed fields. PHP may omit files/fields beyond its parsing limits; handlers must check required fields and expected file counts.
    • Web-server/reverse-proxy body-size limits also apply. Raising framework maxBytes cannot bypass them.

    The request layer returns HTTP 413 when a POST exceeds PHP's configured post_max_size, rather than treating PHP's discarded body as an empty form. Per-file PHP size failures and framework size failures also return 413; partial files, disallowed types, invalid images/packages, empty files, and untrusted local-file sources return 422. Malformed file-field structures return

    1. Server receive/storage failures throw and use the standard logged,

    generic HTTP 500 response. Application-required file errors should be explicitly reported by the handler, as in the example above.

    Multipart support is for normal POST web routes, preserving session/CSRF behavior. The separate /api/* router remains JSON-only and rejects multipart bodies with HTTP 415 (or 413 when its request-size limit is exceeded). Native PHP does not populate this API for raw PUT/PATCH uploads, chunked upload protocols, remote URLs, or base64 JSON file payloads.

    String Manipulation

    Use the native $app->strings service, or instantiate PBreeze\Strings after bootstrap. It accepts UTF-8 strings and throws InvalidArgumentException for malformed encoding instead of silently replacing bytes. No Composer dependencies are used. Case conversion requires mbstring; grapheme operations, naming helpers, and slug transliteration require intl. The service is stateless and construction does not require either extension.

    $strings = $app->strings;
echo $strings->upper('Straße');                   // STRASSE
echo $strings->lower('ÉLÈVE');                    // élève
echo $strings->title('hello WORLD');              // Hello World
echo $strings->trim("\u{00a0} Ada \u{2003}");      // Ada
echo $strings->length("e\u{0301}");               // 1 visible character
echo $strings->slice('Hello world', 6);           // world
echo $strings->slice('Hello world', -5);          // world

    length(), slice(), and truncate() use Unicode grapheme clusters: combining accents and joined emoji are not split into individual code points. Offsets are zero-based; negative offsets count from the end. A null slice length includes the remainder; a negative length omits that many characters from the end. Out-of-range offsets return an empty string. Case conversion follows Unicode mappings, not locale-specific Turkish/Dutch rules, and can expand characters (ß becomes SS). No method changes global locale, encoding, or input data.

    Matching, Extraction, and Replacement

    $strings->contains('Hello café', 'café');         // true
$strings->startsWith('report.csv', 'report');     // true
$strings->endsWith('report.csv', '.csv');          // true
$strings->before('one/two/three', '/');            // one
$strings->after('one/two/three', '/');             // two/three
$strings->replace('Hello Ada, Ada!', 'Ada', 'Lin'); // Hello Lin, Lin!

    Matching is literal and case-sensitive, without regex interpretation or automatic Unicode normalization. Visually identical composed/decomposed characters may therefore differ. Empty needles match in contains(), startsWith(), and endsWith(), including against an empty string. before() and after() use the first occurrence and return the original text when absent. Empty extraction delimiters and replacement searches throw; an empty replacement deletes each occurrence. replace() changes all nonoverlapping occurrences. Unicode whitespace trimming removes leading and trailing whitespace/separators, not internal whitespace or zero-width marks.

    Truncation, Slugs, and Naming

    $strings->truncate('Hello world', 8);             // Hello...
$strings->truncate('Hello world', 5, '');         // Hello
$strings->truncate('Hello world', 2);             // ..
$strings->slug(' Crème brûlée! ');                // creme-brulee
$strings->slug('Hello World', '_');               // hello_world
$strings->snake('HTTPServerID');                  // http_server_id
$strings->camel('HTTP_server_ID');                // httpServerId
$strings->studly('hello-world');                  // HelloWorld

    The truncation limit includes the suffix (default ...), measured in visible characters. A zero limit produces empty text when truncation is needed; negative limits throw. An oversized suffix is itself cut to fit. Short text is returned unchanged, with no added suffix.

    Slugs transliterate through ICU into lowercase ASCII letters/digits, collapse other characters into a hyphen or underscore, and trim outer separators. Punctuation-only or untransliterable input can yield an empty slug. ICU versions can change transliteration results. Slugs are not guaranteed unique: validate the result and enforce application/database uniqueness. They are not file-path validation or authorization.

    Naming helpers split separator runs, lowercase-to-uppercase boundaries, and acronym-to-word boundaries (HTTPServer becomes HTTP, Server). They retain Unicode letters/marks/numbers, normalize word casing, and do not transliterate. Separator-only input becomes empty. Digits remain with their preceding word unless followed by an uppercase letter.

    Cryptographic Random Strings

    $token = $strings->random();                      // 32 alphanumeric characters
$hex = $strings->random(64, '0123456789abcdef');   // 64 hex characters

    random() uses native random_bytes() and rejection sampling to avoid alphabet-selection bias, not rand() or mt_rand(). Length must be 1..65536; the alphabet must contain 2..94 distinct printable non-space ASCII characters. Duplicate characters, Unicode alphabets, whitespace, and invalid lengths throw. Random-source failures propagate. Choose sufficient length/alphabet entropy for your use case; this does not add expiry, hashing, uniqueness guarantees, or authorization. Continue using the built-in authentication/API token services for those flows, and do not log secrets.

    Using Strings in Views

    $strings is reserved and available automatically in both PHP and Breeze views, including layouts and partials. Render data cannot override it.

    <h1>{{ $strings->title($title) }}</h1>
<p>{{ $strings->truncate($description, 160) }}</p>

    Plain PHP views should use e($strings->upper($title)). String operations do not escape HTML, sanitize rich text, or make SQL/URLs safe; keep normal context-appropriate output escaping and parameter binding.

    Date, Time, Money, and Decimal Formatting

    The shared $app->format service uses native PHP Intl/ICU without Composer or external packages. Defaults are en-US and UTC; configure them in your local .env:

    APP_LOCALE=en-US
APP_TIMEZONE=UTC

    The application configuration uses locale and timezone keys. You can also create a standalone formatter:

    $format = new \PBreeze\Formatter(locale: 'de-DE', timezone: 'Europe/Berlin');

    Use language tags such as en-US, nl-NL, de-DE, fr-FR, hi-IN, or ar-EG. Optional script and region subtags are supported; ICU extensions and locale keywords are not. ICU may fall back to a supported parent locale; an unsupported language throws instead of silently using the machine's default. Use IANA time zone identifiers such as UTC, America/New_York, or Europe/Amsterdam, not ambiguous abbreviations or numeric UTC offsets. Neither formatter creation nor individual calls change PHP's global time zone or Intl's global locale. Missing Intl is reported when formatting is requested, so unrelated framework features do not require it.

    Dates and Times

    $date = new \DateTimeImmutable('2026-11-13T15:45:06+00:00');

$app->format->date($date, 'short'); // 11/13/26
$app->format->date($date);          // Nov 13, 2026
$app->format->date($date, 'long');   // November 13, 2026
$app->format->date($date, 'full');   // Friday, November 13, 2026
$app->format->time($date, 'short');
$app->format->dateTime($date);

$app->format->date($date, 'short', locale: 'de-DE'); // 13.11.26
$app->format->dateTime(
    $date,
    locale: 'en-US',
    timezone: 'America/New_York',
    pattern: 'yyyy-MM-dd HH:mm:ss XXX',
); // 2026-11-13 10:45:06 -05:00

$app->format->dateTime(0, pattern: 'yyyy-MM-dd HH:mm:ss'); // 1970-01-01 00:00:00

    Inputs are DateTimeInterface objects or integer Unix timestamps in seconds. Strings are intentionally not parsed; construct and validate your dates explicitly. Dates are formatted in the configured or overridden time zone, not necessarily the input object's zone, without mutating that object. IANA daylight-saving rules apply.

    date() and time() default to medium. dateTime() defaults to a medium date and short time. Styles are short, medium, long, and full; for dateTime(), either part may be none. At least one part must be visible unless a custom pattern is supplied.

    The optional pattern uses **ICU syntax, not PHP date() syntax**. For example, yyyy-MM-dd is a numeric date and HH:mm:ss is 24-hour time. Quote literal text using ICU apostrophe rules. A pattern overrides the style layout and must contain 1 to 256 UTF-8 bytes without control characters. Localized punctuation, spacing, and names can vary with the installed ICU version. The calendar is explicitly Gregorian.

    Decimal Numbers and Percentages

    $app->format->decimal('1234.5');                       // 1,234.50
$app->format->decimal('1234.5', precision: 3);         // 1,234.500
$app->format->decimal(1234, precision: 0);             // 1,234
$app->format->decimal('1234.5', locale: 'de-DE');       // 1.234,50
$app->format->decimal('12345678.5', locale: 'hi-IN');   // 1,23,45,678.50
$app->format->decimal('1234.5', grouping: false);      // 1234.50
$app->format->decimal('1.005');                        // 1.01
$app->format->decimal('-1.005');                       // -1.01

$app->format->percent('0.125');                       // 12.50%
$app->format->percent('0.125', precision: 1);          // 12.5%
$app->format->percent('0.125', locale: 'de-DE');        // 12,50 %

    Decimal and percent inputs are integers or decimal strings. The precision range is 0 through 20, defaulting to exactly 2 fractional digits. Rounding is half away from zero, performed on strings without binary floating-point conversion. Negative values that round to zero display as positive zero. Percent inputs are ratios: 1 means 100%, not 1%.

    Grouping sizes, decimal/group separators, digits, signs, and percent placement follow ICU locale rules. Some locales use nonbreaking spaces or non-Latin digits, and some do not group four-digit numbers. Do not compare rendered values after replacing those characters with ordinary spaces.

    Money

    $app->format->money('1234.565', 'USD');                 // $1,234.57
$app->format->money('1.005', 'USD');                    // $1.01
$app->format->money('1234.5', 'EUR', locale: 'de-DE');   // 1.234,50 €
$app->format->money('1234.5', 'JPY');                   // ¥1,235
$app->format->money('1.2345', 'KWD');                   // KWD 1.235
$app->format->money('1234.5', grouping: false);         // $1234.50

$app->format->moneyMinor(12345, 'USD');                 // $123.45
$app->format->moneyMinor(-1, 'USD');                    // -$0.01
$app->format->moneyMinor(12345, 'JPY');                 // ¥12,345
$app->format->moneyMinor(12345, 'KWD');                 // KWD 12.345

    money() accepts a decimal string in major currency units; moneyMinor() accepts an integer in the currency's minor units. Floats are not supported inputs: keep database decimal amounts as strings, and do not compute money with floating-point arithmetic before calling the formatter. The default currency is USD. Pass uppercase three-letter ISO 4217 codes; syntax is checked, but this is not a registry of currently active currencies. Unknown codes use ICU's generic currency formatting.

    ICU supplies standard currency precision: typically 2 digits for USD/EUR, 0 for JPY, 3 for KWD, and 4 for CLF. This is not a universal cents conversion. String rounding remains exact even beyond PHP's integer range or Excel's numeric precision; integer minor units are limited to PHP's integer range. Currency position, symbol/code, spacing, negative sign, and digits follow the requested locale. Space characters in the examples above may actually be nonbreaking spaces. No currency conversion, accounting arithmetic, cash rounding increments, or localized-input parsing is performed.

    For all numeric methods, decimal strings use ASCII digits, an optional leading minus, and an optional period followed by fractional digits. No whitespace, leading plus, grouping separators, or exponent notation is accepted. Inputs are limited to 1,024 bytes. Decimal and percentage inputs also reject floats: use strings when fractional precision matters. For example, "0.1" is valid; "1,25", ".5", and "1e3" are not.

    Saving and Downloading

    use PBreeze\Documents\Documents;

$file = Documents::json(['name' => 'Ada', 'active' => true]);
$file->save($app->root . '/storage/people.json');

// Return this from a web controller action.
return $file->download('people.json');

    save() creates a new local file exclusively: existing files and symlinks are never overwritten. The parent directory must already exist. Relative paths use PHP's current working directory; use an application-root-based path for predictable behavior. Both path separators are accepted. Stream-wrapper URLs, drive-relative Windows paths, control characters, and nonportable basenames are rejected. Files receive 0600 permissions on Linux; restrict inherited ACLs on Windows. Incomplete writes are removed, and failures throw exceptions.

    download() returns a normal PBreeze\Response with an attachment disposition, the correct media type and byte length, nosniff, and no-store. UTF-8 filenames use filename* with an ASCII fallback; filenames cannot contain paths or control characters. Give the filename the matching extension. Return the response rather than printing file bytes yourself, so normal HEAD handling and response headers remain intact.

    Register downloads on ordinary web routes, for example:

    $router->get('/reports/people.csv', $app->auth->protect(static function (\PBreeze\Request $request): \PBreeze\Response {
    return \PBreeze\Documents\Documents::csv([
        ['Name', 'Active'],
        ['Ada', true],
    ])->download('people.csv');
}));

    Apply the appropriate authentication and record-level authorization before exporting private data. The separate /api/* router still requires JSON responses; it is not a binary-download router.

    JSON, CSV, and XML

    use PBreeze\Documents\Documents;

Documents::json(['total' => 12.5, 'active' => true, 'notes' => null])

    ['Lin', null, false],

    CSV uses UTF-8 without a BOM, CRLF record endings, doubled double quotes, and no proprietary backslash escape. Delimiters may be comma, semicolon, tab, or pipe. This intentionally changes those text values; numeric cells remain numeric text. Use protectFormulas: false only for trusted data when an exact raw export is necessary. Importer behavior varies: retain protection when opening untrusted CSV in spreadsheet software.

    XML string keys become element names and integer keys become <item>: the people list above becomes <people><item><name>Ada</name>...</item>...</people>. Null produces an empty element. Attributes, namespace declarations, raw markup, DTDs, and entities are not accepted as data features. Text is escaped, not interpreted.

    JSON preserves native JSON value types and throws on invalid UTF-8, recursive data, unsupported values, or nonfinite numbers. CSV, XML, and office-document text must be valid UTF-8 containing only XML 1.0 characters; unsupported cell types and nonfinite numbers throw instead of being silently converted.

    Creating, Viewing, and Revoking Tokens

    First register at /register and verify the email address through the existing verification email. Tokens are intentionally issued only through the admin CLI: there is no public password/token endpoint, OAuth server, or additional login without CAPTCHA. Use the numeric ID from the users table, not the email address:

    php breeze api:token 1 laptop 30
php breeze api:tokens 1
php breeze api:revoke 12

    api:token <user-ID> [name] [days] displays the new pbz_... token once. The default expiration is 30 days; the allowed range is 1–365 days. api:tokens displays only the ID, user ID, name, and timestamps, including for expired tokens; api:revoke uses the token ID, not the user ID. Store the token in a secret store, not in source code, query strings, shell history, or shared terminal logs. The database stores only the SHA-256 hash.

    For an API client, send the token in the Authorization header using bearer authentication. Cookies, query parameters, and CSRF tokens never authenticate API requests. A token is valid only while the user exists, the email address is verified, the expiration date has not passed, and the stored session_version matches. Password reset therefore also invalidates all existing API tokens. Web logout removes only the web session; revoke API tokens separately. Tokens have no scopes/roles: they represent the user. Always implement your own per-object authorization; a valid token does not automatically grant access to other users' data.

    Creating an API with the CLI

    php breeze make:api Products
php breeze routes
php breeze api:openapi > openapi.json

    This creates:

    • app/controllers/api/ProductsApiController.php;
    • routes/api/products.php with GET/POST /api/products and GET/PUT/DELETE /api/products/{id};
    • an explicit require in routes/api.php.

    No directory scans, autoloading, or Composer. The route module registers handlers and OpenAPI together through $api->add(). All generated actions require a bearer token by default. They intentionally return HTTP 501 until you implement them: no accidental public CRUD or success message without persistence. Then also replace the generated 501 response descriptions and generic requestBody schemas with your actual fields, responses, and validation. The generator rejects existing files, reserved names, and route conflicts; the registry is locked during the change. Run generators during development, not as a replacement for an atomic production deployment.

    A custom route definition in an explicitly loaded API module:

    $api->add('POST', '/api/echo', static function (\PBreeze\Request $request): \PBreeze\Response {
    $data = \PBreeze\Api::validate($request, [
        'message' => 'required|string|min:2|max:200',
    ]);
    $user = $request->apiUser();
    return \PBreeze\Response::json(['data' => [
        'message' => $data['message'],
        'user_id' => $user['id'],
    ]]);
}, [
    'summary' => 'Echo a validated message',
    'operationId' => 'echoMessage',
    'requestBody' => ['required' => true, 'content' => [
        'application/json' => ['schema' => [
            'type' => 'object',
            'required' => ['message'],
            'properties' => ['message' => ['type' => 'string', 'minLength' => 2, 'maxLength' => 200]],
        ]],
    ]],
    'responses' => ['200' => ['description' => 'Validated message and current user ID']],
]);

    Pass false as the fifth argument only for intentionally public endpoints. summary, a unique operationId, and responses are required. Path parameters automatically get a required OpenAPI string definition; you can specify them further through parameters. Bearer security is derived from the actual route protection, not from manually set metadata. OpenAPI describes the contract but does not perform validation. Api::validate() uses the existing native Validator, returns only the specified fields, and reports invalid input with HTTP 422 and field details. Nested JSON objects remain stdClass; validate them explicitly.

    JSON, Errors, and Limits

    Nonempty API bodies require Content-Type: application/json and a JSON object. Invalid JSON returns 400, other body types 415, and bodies larger than 1 MiB 413. Empty bodies without a JSON content type are allowed, for example with DELETE. Also configure limits in PHP, the web server, and the proxy: PHP may process uploads before application code runs. Normally parsed API requests have a fixed database rate limit of 120 requests per direct client IP per calendar minute; after that, HTTP 429 with Retry-After. Documentation and OpenAPI are exempt and do not require a database. REMOTE_ADDR is used, not unverified proxy headers. Clients behind a proxy therefore share the proxy IP; apply additional limits at the edge. This limit is not DDoS protection.

    API errors consistently use:

    {"error":{"status":422,"message":"Check your input.","details":{"message":["This field is required."]}}}

    details is present only for validation errors. Unknown routes return JSON 404, incorrect methods return JSON 405 with Allow, and missing/invalid tokens return JSON 401 with WWW-Authenticate. Unexpected errors are logged and return a generic JSON 500, even in debug mode. Use Response::json() for custom API responses; for an empty 204, use an empty Response with a JSON content type. API requests do not start a session or set a session cookie. The existing web CSRF check remains unchanged. There is intentionally no automatic CORS or preflight configuration; clients on a different origin require an explicit, carefully restricted policy.

    Breeze Templates

    The native template engine supports layouts, sections, includes, components, slots, conditionals, and loops. No dependencies, eval(), or Composer: templates are compiled to PHP and executed with require.

    Partials and Components

    An include inherits the variables in the current scope, including loop variables. Explicit data overrides inherited values only inside the include:

    @include('partials.item', ['title' => $item])

    Includes have their own section context; define layout sections in the page itself, not in an include.

    Components receive only the explicit props and their rendered slots. For example, app/views/components/panel.breeze.php:

    <section>
    <h2>{{ $title }}</h2>
    {!! $slot !!}
    @if(isset($footer))
        <footer>{!! $footer !!}</footer>

</section>

    Usage:

    @component('components.panel', ['title' => 'Latest messages'])
    <p>{{ $intro }}</p>
    @slot('footer')
        <a href="/berichten">All messages</a>

Slot names are unique variable names without a leading underscore; an @slot must be directly inside a component. You can nest different components. Variables inside the invocation content come from the page, not from the component's props.

    Compilation and Cache

    The cache is in storage/views/ by default, outside public/. On Linux, the directory and new cache files get 0700 and 0600; on Windows, the folder's NTFS ACLs apply. Make sure the PHP service user can create and read this cache. Align ownership and permissions for the CLI and web server; never give uploaders write access to this directory.

    The cache name contains a hash of the template path, content, and compiler version. Changed templates are automatically recompiled, even when their modification time stays the same.     Sessions and CSRF

    All POST, PUT, PATCH, and DELETE requests require a session token. Only GET, HEAD, and OPTIONS are exempt; do not modify data with them.

    <form action="/berichten" method="post">
    <?= csrf_field($session) ?>
    <button type="submit">Save</button>
</form>

    Pass $this->app->session to the view as session. A JSON client can send the same token as X-CSRF-Token, along with the session cookie. An incorrect or missing token returns 419. There are intentionally no default CSRF exceptions or unprotected API routes. For a form with bot protection, also send the CAPTCHA fields and empty honeypot; a CSRF token alone is not sufficient.

    $this->app->session->put('notice', 'Saved');
$notice = $this->app->session->get('notice');
$this->app->session->regenerate();

    Authentication automatically regenerates the session ID and CSRF token on login and logout. Existing session data is cleared at that time. A CSRF token does not replace access control; explicitly protect your routes.

    CAPTCHA and Honeypot

    The selected forms use both controls: registration, login, forgot password, verification-email resend, and the name form on the home page. Logout, confirming a verification link, and saving a new password remain protected by CSRF and their own guards/tokens and existing limits, without an additional CAPTCHA.

    The CAPTCHA is entirely native PHP: no external services, JavaScript, GD, fonts, Composer, or API key. GET /captcha/{id} returns a local SVG with six random characters, drawn as vector paths with light noise. The solution is not present as text or metadata in the HTML/SVG; the session stores its SHA-256 hash, along with the SVG, form name, and expiration time. Ambiguous characters 0, 1, I, and O are not used.

    User Experience

    • Enter the six characters; capitalization does not matter. Leading and trailing spaces are ignored.
    • A code is valid for five minutes and works only in the same session and for the same form purpose.
    • Each submission attempt consumes the supplied code, even with an incorrect answer, a filled honeypot, or another validation error. The form then displays a new code; password fields remain empty.
    • Show another code refreshes through a CSRF-protected POST without performing the form action, logging in, or sending email. The browser does not need to validate other fields first. Name/email values are preserved; passwords are not. The form's old code is revoked.
    • Fetching images or making HEAD requests does not consume a code. Images are session-bound and are not cached.
    • Up to twelve unexpired codes per session support multiple tabs. If there are more, the oldest code expires. Up to sixty new codes per session per minute; after that, 429 with Retry-After is returned.
    • The website honeypot must be present as an empty string. The field is visually hidden, removed from the tab order, and hidden from screen readers; autocomplete is disabled. Filled, missing, or incorrectly typed values are rejected.

    Bot-check errors return 422 with a generic message and a new form. Missing/incorrect CSRF remains 419 and is checked earlier. No success message is displayed for a blocked action. The existing database-backed authentication limits remain active when the bot check passes.

    Limitations: a simple SVG CAPTCHA can be solved by OCR, pattern recognition, or human-solving services. The honeypot is an additional hurdle, not proof that a visitor is human. The creation limit is session-bound; new cookies bypass that limit. Also use request limits per IP and abuse detection on your trusted web server/proxy. A visual CAPTCHA is not independently usable by blind users: there is no audio or equivalent accessible verification route yet. Provide one before offering these forms to an audience for whom visual verification is inaccessible; do not add an unprotected bypass.

    Sending Email

    Authentication emails always go through the existing database queue, even if MAIL_LOG=false. Configure MAIL_FROM and SMTP as described below, and run this regularly through cron or Windows Task Scheduler:

    php breeze mail:work 50

    Successful submission means the email is queued, not that it has been delivered. Without working SMTP configuration/worker, the user receives no email. No external email is sent during installation or tests. New accounts and their verification email are stored together: if queuing fails, registration is rolled back. Database and configuration errors are logged as server errors, not displayed as successful submissions.

    Tokens contain 32 cryptographically random bytes and are stored only as SHA-256 hashes in auth_tokens. Verification tokens are valid for 24 hours, reset tokens for 30 minutes, measured from the request. They are single-use; a new request replaces the previous link for the same purpose. The worker must therefore run promptly. Reset invalidates all existing login sessions for the account and signs out the requester. Reset does not automatically verify the email address.

    Warning: the sendable email in emails necessarily contains the full link. Protect the database, backups, and CLI access as secrets. Delete old emails according to your retention policy and configure web server/proxy logs not to retain token-bearing query strings. Authentication pages use no-store and Referrer-Policy: no-referrer. Disable debug in production.

    Protecting Custom Routes

    $router->get('/dashboard', $app->auth->protect([$controller, 'dashboard']));

$router->get('/onboarding', $app->auth->protect([$controller, 'onboarding'], false));

    The guard redirects guests to /login and unverified accounts to /email/verify. There is no automatic redirect back to a supplied URL. Roles, per-object permissions, MFA, remember-me, and external providers are not included; add authorization before exposing user data.

    Sessions expire after 30 minutes of inactivity or a maximum of 12 hours from login. Each check reads the current user and session version from the database. Deleted users and sessions with an outdated version lose access.

    ActionLimit
    Registration5 per IP per hour

    PostgreSQL

    PostgreSQL is supported through the native pdo_pgsql PHP extension and libpq on Windows and Linux, without Composer. Enable the extension in both CLI and web PHP.     DB_CONNECTION=pgsql

    DB_SSLROOTCERT is optional: empty uses libpq's default root-certificate lookup. On Windows, use forward-slash paths such as C:/certificates/root.crt. SQL Server's DB_ENCRYPT/DB_TRUST_SERVER_CERTIFICATE settings do not affect PostgreSQL.

    Connections use TCP with a hostname or IPv4 address, not Unix socket paths or arbitrary DSN fragments. Set DB_PORT=5432: the example file explicitly uses 3306 for MySQL. If the variable is entirely absent, the configured driver selects the appropriate default. Connection setup has a 15-second timeout, UTF-8 client encoding, and UTC session time zone. Switching drivers does not transfer data.

    PostgreSQL migrations and bookkeeping run transactionally. A database-scoped session advisory lock prevents overlapping PBreeze migration processes, in addition to the local file lock. Operations PostgreSQL prohibits inside a transaction (for example CREATE INDEX CONCURRENTLY) cannot be used in normal migrations; plan those separately with appropriate operational safeguards.

    The query builder uses double-quoted simple identifiers, LIMIT/OFFSET, bound values, and INSERT ... RETURNING for generated keys. Custom incrementing and nonincrementing ORM keys work through the same APIs as the other databases. Use explicit stable ordering for pagination.

    Raw SQL passed to PDO or execute() is not translated. Use PostgreSQL SQL in custom migrations, seeders, and queries. PostgreSQL text cannot contain NUL bytes; encode binary application data or use an application-specific bytea binding path rather than storing it as text.

    Native ORM and Query Builder

    The ORM consists of framework/Query.php and framework/Model.php, explicitly loaded in the bootstrap. Each query and model receives the existing Database instance. There are no packages, autoloading, global connections, schema inspection, or automatic migrations. The SQL is designed for SQLite, MySQL, SQL Server, and PostgreSQL; the existing cross-platform PDO configuration remains authoritative.

    Table Queries: Arrays

    $query = $app->db->table('notes');
$id = $query->insert(['title' => 'My note']);
$note = $query->find($id);          // array of null
$note = $query->findOrFail($id);    // array of RecordNotFoundException

$recent = $query->where('id', '>', 0)
    ->where('title', 'LIKE', '%note%')
    ->orderBy('id', 'desc')
    ->limit(20)
    ->get();

$query->where('id', $id)->update(['title' => 'Updated']); // row count
$query->where('id', $id)->delete();                       // row count

    Queries are immutable: where, orderBy, limit, and offset return a new query. Therefore, retain the result or chain the calls. All where conditions are combined with AND:

    $query = $app->db->table('notes');
$filtered = $query->whereIn('id', [1, 2, 3])->whereNotNull('title');
$first = $filtered->first();            // array or null
$first = $filtered->firstOrFail();      // exception if absent
$count = $filtered->count();            // int
$exists = $filtered->exists();          // bool
$rows = $filtered->orderBy('id')->limit(10)->offset(10)->get();

    Supported operators: =, !=, <>, <, <=, >, >=, LIKE, NOT LIKE. where('column', $value) uses =. where('column', null) and where('column', '!=', null) use IS NULL and IS NOT NULL, respectively; explicit whereNull/whereNotNull are also available. whereIn expects a list of up to 500 non-null values; an empty list finds or modifies no rows. LIKE wildcards % and _ retain their SQL meaning: parameter binding does not make them literal.

    Values are bound as int, bool, string, or null; floats are bound as textual numbers. Arrays, objects, resources, INF, and NAN are rejected. Table and column names must be simple identifiers (letters, digits, or underscores, not starting with a digit); they are quoted. Operators and sort directions are checked. The builder does not accept SQL fragments, joins, aliases, schema/table prefixes, OR groups, or raw expressions. For more complex SQL, intentionally use Database::execute() with bindings. Even with valid column names, choose yourself which ones a user may query or modify: identifier validation is not authorization.

    update and delete without an explicit WHERE are rejected. Writes with sorting, limits, or offsets are also rejected so conditions are never silently ignored. insert/create does not accept filters, sorting, or pagination. insert([]) uses database defaults and returns the PDO insert ID (int if representable, otherwise string); with manual keys, use the supplied key, not this driver-dependent ID. get() retrieves all matching rows unless you specify a limit. count() and exists() use the filters and ignore read limits, offsets, and sorting. offset with get() requires an explicit limit.

    Models: Objects

    php breeze make:model Article

    The generator creates a Model subclass with a snake_case name plus s as the default table name. There is intentionally no language-dependent pluralization: check the name, create the table through a migration, and populate $fillable. The default list is empty: no fields are mass assignable.

    Example for a custom articles table with the columns shown:

    <?php
declare(strict_types=1);

namespace App\Models;

final class Article extends \PBreeze\Model
{
    protected string $table = 'articles';
    protected bool $timestamps = true;
    protected array $fillable = ['author_id', 'title', 'published', 'metadata', 'published_at'];
    protected array $hidden = ['metadata'];
    protected array $casts = [
        'id' => 'int',
        'author_id' => 'int',
        'published' => 'bool',
        'metadata' => 'json',
        'published_at' => 'datetime',
        'created_at' => 'datetime',
        'updated_at' => 'datetime',
    ];

    public function author(): \PBreeze\Query
    {
        return $this->belongsTo(Author::class, 'author_id');
    }
}

    By default, a model has primary key id, $incrementing = true, and $timestamps = false. Enable timestamps only if both columns created_at and updated_at exist. Use UTC fields that can store values in Y-m-d H:i:s. Define foreign keys and database defaults explicitly in your migration. A model does not run schema migrations or content validation.

    require_once $app->root . '/app/models/Article.php';
require_once $app->root . '/app/models/Author.php';

$articles = new \App\Models\Article($app->db);
$article = $articles->create([
    'author_id' => 1,
    'title' => 'My first article',
    'published' => false,
    'metadata' => ['tags' => ['php']],
    'published_at' => null,
]);

$article->title = 'A new title'; // checks fillable and cast
$changes = $article->dirty();        // changed fields in storage format
$article->save();                    // insert new model; otherwise changes only
$article->update(['published' => true]);
$article->refresh();                 // reload; overwrites local changes

$found = $articles->query()->findOrFail($article->id); // Article-object
$list = $articles->query()->where('published', true)->orderBy('id')->get();
$article->delete();                  // deletes the row; do not save again

    create() always creates a new model, even if you call it on a loaded record. query()->create() is an equivalent alternative. save(), update(), and delete() return true on success and explicitly fail on database errors. Reading an unknown/unloaded field throws a LogicException. exists() on a model returns the locally known saved state; for a current database check, use query()->where(...)->exists(). After a write, defaults and database values are reloaded. Saving an unchanged model writes nothing. refresh() or a write on a deleted row throws RecordNotFoundException; an unchanged save() does not check again. This exception does not automatically produce an HTTP 404: translate it in your controller to HttpException(404, ...) if desired.

    fill() and field assignment accept only $fillable. Unknown fields are not silently ignored. The primary key of a saved model and automatic timestamps are not writable. For manual/string keys, set $incrementing = false, choose $primaryKey, and add that key to $fillable for creation.

    Model queries also support filtered bulk update/delete. update checks fillable fields and casts, but works without model instances: automatic timestamps are not updated. Use save() or update() on a loaded model if you want that. Primary-key updates through a model query are always rejected. Model protections do not apply to a table query. insert() is only for table queries; use create() for model queries.

    Relationships

    Define relationships with explicit model classes and keys. The related class must itself be loaded through require_once:

    final class Author extends \PBreeze\Model
{
    protected string $table = 'authors';
    protected array $fillable = ['name'];

    public function articles(): \PBreeze\Query
    {
        return $this->hasMany(Article::class, 'author_id');
    }
}

$author = $article->author()->first(); // Author of null
$authorArticles = $author->articles()->where('published', true)->get();

    hasMany(Related::class, foreignKey, localKey) uses the model's primary key as localKey by default. belongsTo(Related::class, foreignKey, ownerKey) uses the related model's primary key by default. Both return a new, filterable model query on the same database connection. A null relationship key returns no results. Relationships on unsaved models are rejected; records are not automatically saved or associated. For a nullable belongsTo, check for null yourself before navigating further.

    There is no implicit lazy loading through properties, eager loading, relationship cache, cascade-save, polymorphism, or many-to-many API. Relationship queries inside a loop therefore run as separate queries; for larger lists, deliberately fetch the required rows in batches with whereIn. Cascades and referential integrity belong in your migrations.

    Encryption

    The native Encryption service uses AES-256-GCM through OpenSSL: 256-bit keys, a new cryptographically random 12-byte nonce per encryption, and a full 16-byte authentication tag. Data is returned only if the integrity check succeeds. There is no fallback to plaintext, a default key, or insecure encryption.

    Creating and Storing a Key

    php breeze key:generate

    This displays one APP_KEY=base64:... line. Copy it to your local .env or set APP_KEY through your deployment's environment configuration/secret store. The command changes no files and never overwrites an existing key. Each execution displays a new key; do not casually replace a key that already protects data. --force is not accepted. Run the command in a private terminal, not in shared CI logs.

    The key must contain exactly 32 random bytes, canonically base64-encoded with the base64: prefix; a password or custom text key is rejected. No key is automatically generated at boot or per request. Without APP_KEY, the framework continues to work until you use encryption or a non-null encrypted cast; then an explicit EncryptionException is thrown.

    Store a secure key backup separately from the database. Share the same key with the web app, CLI, and workers that must decrypt the same data; use different keys for different applications/environments. Never commit real keys. Protect .env, environment variables, server logs, and backups; do not dump the application configuration. Encrypted data cannot be recovered without the original key.

    Using the Service

    $encrypted = $app->encryption->encrypt('Confidential text', 'orders:notes');
$plaintext = $app->encryption->decrypt($encrypted, 'orders:notes');

    The optional context is authenticated but not stored in the payload. You must use exactly the same context to decrypt. Choose a fixed, application-specific context to prevent accidental reuse elsewhere. Empty strings, Unicode, and binary strings are supported. The output format is pbreeze:v1: followed by base64 of the nonce, tag, and ciphertext. The prefix/version and context are included as additional authenticated data. Encrypt the same value again and you get a different payload. The format does not use PHP serialization.

    use PBreeze\Encryption;

$encryption = new Encryption($configuredKey);
$encrypted = $encryption->encrypt($value);
$value = $encryption->decrypt($encrypted);

    Invalid/outdated payload formats, truncated or modified data, or an incorrect key or context throw PBreeze\EncryptionException. A genuine operational failure must remain visible; do not catch it and then return empty text or the original ciphertext as if decryption succeeded. Errors contain no key or plaintext. Key and plaintext parameters are marked with SensitiveParameter; the service redacts key data in var_dump and cannot be serialized. This does not replace careful logging practices: your own code can still leak decrypted data.

    Encrypted ORM Casts

    final class Customer extends \PBreeze\Model
{
    protected string $table = 'customers';
    protected array $fillable = ['name', 'private_note', 'preferences'];
    protected array $hidden = ['private_note', 'preferences'];
    protected array $casts = [
        'private_note' => 'encrypted',
        'preferences' => 'encrypted:json',
    ];
}

$customers = new Customer($app->db);
$customer = $customers->create([
    'name' => 'Example',
    'private_note' => 'For internal use only',
    'preferences' => ['language' => 'en'],
]);
$text = $customer->private_note;       // decrypted string
$preferences = $customer->preferences; // decrypted array
$customer->update(['private_note' => 'New text']);

    encrypted accepts strings; encrypted:json accepts arrays. Both preserve null as database NULL. Bulk updates through a model query also use these casts. Hydration/refresh validates ciphertext without re-encrypting: unchanged data is not marked dirty and does not change during another field update. Assigning the same decrypted value again preserves the existing ciphertext. Deliberately assign new content if you want to replace it.

    Use TEXT or, for large payloads, MySQL LONGTEXT, not the original short VARCHAR: encryption adds 28 bytes and a prefix, and base64 further increases the payload. The exact storage length is 11 + 4 * ceil((28 + bytes) / 3). No existing columns or data are modified automatically.

    The ORM context contains the table name, column name, and cast type. Moving ciphertext to another table/column or changing the cast type is therefore rejected. The context does not contain a row ID: moving data between rows in the same column or restoring older valid data is not prevented. Encryption does not protect against replay, deletion, a compromised application, or an attacker with access to both data and key.

    Encryption does not automatically hide fields. Reading and toArray()/JSON return plaintext unless you add the field to $hidden. dirty() and direct $app->db->table(...) queries use the storage format. Table queries and handwritten SQL do not apply encrypted casts: use models when writing to encrypted columns.

    Because ciphertext is random, comparisons, whereIn with values, LIKE, sorting, and relationship keys on encrypted model fields are unusable; the model query explicitly rejects them. whereNull/whereNotNull and an empty whereIn remain usable. Primary keys and automatic timestamp columns must not have an encrypted cast. Also do not use a foreign/unique index as a logical plaintext comparison. Existing login email addresses, password hashes, reset/verification token hashes, and mail queue remain intentionally unchanged. Passwords remain one-way hashed, not reversibly encrypted.

    For a custom database instance, explicitly pass the same service:

    $db = new \PBreeze\Database($root, $databaseConfig, $encryption);

    Existing Data and Key Rotation

    Adding an encrypted cast to an existing plaintext column does not migrate anything: reading then intentionally fails. Create your own controlled migration to sufficiently large columns and encrypt existing values with the correct context. Back up first and test on a copy. Renaming a table/column also requires decrypting with the old context and encrypting with the new context.

    There is no automatic key rotation, keyring, or migration command. For a controlled rotation, stop all writers/workers, safely store the old key, decrypt with the old service, and encrypt with the new service using the same context. Verify all records/backups, switch all processes to the new key, and only then resume writes. Replacing APP_KEY alone makes previously encrypted data unreadable.

    Sending or Queuing from PHP

    Through $app in routes, or $this->app in controllers:

    $message = $app->mail->compose([
    'to' => ['recipient@example.com'],
    'subject' => 'Welcome',
    'text' => 'Welcome to our application.',
    'html' => '<p>Welcome to our application.</p>',
]);

$id = $app->mail->send($message);   // Send immediately through SMTP.
// OR:
$id = $app->mail->queue($message);  // Store only; send later through the CLI.

    from is optional in compose() and defaults to MAIL_FROM. You can also directly use new \PBreeze\Mail\Message(...). Use bare ASCII email addresses without display names; up to 100 recipients. Subjects and bodies are UTF-8. You can provide text, HTML, or both; providing both creates a multipart/alternative message. Subjects must not contain control characters and are limited to 500 bytes; bodies are limited to 5 MiB total. Headers are encoded and MIME bodies are base64-encoded. Cc, Bcc, attachments, and supplied headers are not included.

    MAIL_LOG=true is the default:

    • Directly sent outgoing messages are stored in emails before SMTP. The table stores the sender, recipients, subject, text, HTML, Message-ID, status, attempts, timestamps, and a sanitized error message.
    • A database error before sending prevents the message from being sent

    without a log. An SMTP error throws an exception and remains in the table.

    • Retrieved incoming messages are stored in the same table.
    • With logging enabled, send() returns the ID; otherwise, it returns null.

    With MAIL_LOG=false, direct sending and IMAP retrieval do not use an email table. **Explicitly using queue() or mail:queue always stores a message**: a database queue cannot operate without storage. All stored outgoing messages can still be sent through the CLI, and their status is updated. Settings and passwords are not stored in the email table.

    sendingAtomically claimed by a sending process.
    sentSMTP returned a 250 confirmation after DATA; delivery is not guaranteed.
    failedNot sent or explicitly rejected by SMTP.
    uncertainConnection lost after DATA began; SMTP may already have accepted the email.
    receivedRetrieved through IMAP; never directly sendable.
    php breeze mail:retry 1
php breeze mail:send 1

    mail:retry changes only failed back to queued. sent and incoming emails cannot be resent with these commands. Create a new message for an intentional resend. If a process crashes, the status may remain sending. In that case, first check the SMTP server and stop active workers; only then deliberately use mail:retry ID --force for sending or uncertain. This can cause duplicate delivery. There is intentionally no automatic timeout retry. The Message-ID remains the same on retries, but that does not guarantee recipient-side deduplication.

    If SMTP accepts the email but saving sent fails, the status remains sending and the caller receives an error. In that case, also check the SMTP server first. Concurrent workers can never claim the same queued row; if a claim conflict occurs, the worker stops explicitly and the next scheduled run can proceed. SMTP acceptance is not the same as delivery: bounces are not processed automatically. Configure SPF, DKIM, and DMARC at the domain/mail server level.

    Reading and Logging the IMAP Inbox

    php breeze mail:fetch 50

    Or from PHP:

    $messages = $app->mail->fetch(50);
foreach ($messages as $message) {
    $id = $message['id'];            // null when MAIL_LOG=false
    $subject = $message['message']['subject'];
    $text = $message['message']['text'];
}

    The client opens the mailbox with EXAMINE and reads BODY.PEEK[]: messages are not marked as read, deleted, or moved. The default is INBOX; other mailbox names are ASCII or pre-encoded IMAP modified UTF-7. When logging is enabled, the oldest UIDs not yet stored are retrieved so repeated batches work through the inbox. Without logging, the most recent UIDs are retrieved and there is no persistent import checkpoint. Limits are 1–1000 messages per run, 50 by default.

    Deduplication uses server, port, account, mailbox, UIDVALIDITY, and UID; the unique database index also protects concurrent imports. A changed UIDVALIDITY or account/server configuration can intentionally cause a new import. Deleted database rows can be imported again. The server is queried with UID SEARCH ALL on each run; metadata is limited to 2 MiB per response.

    Incoming MIME is parsed into text and HTML, including base64, quoted-printable, RFC 2047 headers, and iconv character sets. Attachments are not unpacked; the exact original email remains base64-encoded in raw_message. headers_json stores the original unfolded headers; outgoing emails store structured fields instead of a raw copy. Incoming to_addresses contains the original To header as a single list item, not a validated recipient list. Incoming data is never reused as an outgoing Message.

    The default maximum is 10 MiB raw per message (IMAP_MAX_BYTES), configurable up to 50 MiB; each batch is limited to 50 MiB raw. MIME nesting is limited to 10 and the number of parts to 100. Larger, malformed, or unsupported messages cause an explicit error, not an apparently successful import. A parse/network error during retrieval does not save that batch. If a later database error occurs, earlier inserts in the batch may be retained; deduplication makes the next run safe.

    Protect access to emails, backups, and the CLI: messages may contain confidential data. Base64 is not encryption. Set your own retention period, restricted database permissions, and appropriate storage security. Incoming HTML is not sanitized: never render it directly in your application; display it as text with e() or use a separate, well-sanitized and protected viewer.

    System environment variables take precedence over .env. .env supports NAME=value, optional single/double quotes, and full-line comments.     Production and Security Boundaries

    Deployment checks and readiness

    The framework provides production safeguards, not automatic production configuration. Local .env values are intentionally preserved during upgrades. Run these commands as the deployment/service identity after configuring the environment and before routing traffic to the new release:

    php breeze storage:prepare
php breeze migrate --force
php breeze doctor

    Back up the database first and use backward-compatible migrations during rolling releases. storage:prepare creates only the private storage root and its logs, uploads, and views children. It does not move files, adjust existing ownership, configure sessions, or change database contents.

    doctor prints PASS, WARN, or FAIL for production flags, trusted HTTPS origin, extensions, private storage, database/schema/migration readiness, encryption, mail configuration, and operational concerns. Its exit code is 1 when any check fails and 0 otherwise; review warnings too. It does not create directories, databases, migration tables, or records, send email, or call AI. An SMTP configuration warning is not evidence that real mail delivery works. It checks the CLI PHP installation; verify the web/FPM installation separately. If bootstrap configuration is invalid, the command exits with the normal startup error before diagnostics can run.

    • GET /health: lightweight process liveness only; a 200 does not prove that the database is usable.
    • GET /ready: 200 with {"status":"ready"} only when private storage exists and is readable/writable, the existing database accepts reads, bundled tables exist, and applied migration names match the deployed files. Otherwise it returns 503 with {"status":"not_ready"} and logs safe failure metadata. It never creates a missing SQLite database or runs migrations.
    • Exact GET/HEAD requests to those two probe paths do not start a session or issue a session cookie. HEAD responses have an empty body.

    Restrict probes to your load balancer/monitoring network at the web server. Readiness performs database reads, so set a sensible polling interval and edge rate limits. It does not test SMTP/AI availability, usable free disk space, backup recovery, real writes, or application-specific dependencies. Database network/query deadlines must also be set in the database/server/PHP stack. The framework retains provider/driver-specific timeout behavior rather than claiming a universal probe deadline.

    Persistent storage across releases

    STORAGE_PATH=/srv/pbreeze-data

    Changing STORAGE_PATH does not move existing data. Stop or drain writers, back up and copy uploads and required logs to the new private directory, preserve ownership/ACLs, deploy consistent settings to web and workers, and verify downloads before switching traffic. Compiled views may be regenerated. Do not run view:clear against a cache actively used by other releases; prefer leaving content-addressed cache entries until old workers have drained.

    SQLite is independent: set DB_DATABASE to an absolute persistent file path outside the release and public directories. Do not copy a live SQLite database as an ordinary file without a consistent backup procedure. PHP session storage is also independent: configure the web SAPI's session.save_handler and session.save_path, permissions, and retention. Multiple nodes need shared sessions or appropriate sticky routing and common upload storage. SQLite on network filesystems is not supported.

    MySQL verified TLS: upgrade requirement

    MySQL now defaults to verified TLS. Before upgrading a MySQL installation, configure:

    DB_MYSQL_TLS=required
DB_MYSQL_SSL_CA=/etc/ssl/certs/mysql-ca.pem

    The CA must be a readable local certificate bundle and the server certificate must match DB_HOST. Use a TCP hostname/address; localhost may select a Unix socket instead of TLS. Native PDO verifies the certificate and the framework rejects connections without a negotiated TLS cipher. No plaintext fallback is attempted. Windows certificate paths can use forward slashes.

    Only isolated local development/testing can explicitly set DB_MYSQL_TLS=disabled, with DB_HOST=localhost or 127.0.0.1 and APP_ENV other than production. Production always rejects that opt-out. Programmatic Database settings use tls and ssl_ca; standalone production instances must pass production: true. PostgreSQL and SQL Server keep their existing TLS settings.

    Request limits and reverse proxies

    Every application/json request, including non-API routes, now has a fixed 1 MiB raw-body cap. All API bodies retain that cap. Bounded reads enforce it even without Content-Length; oversized input returns 413. This is separate from the 2 MiB per-upload default: set PHP/web-server multipart limits with appropriate overhead. Edge limits must reject oversized traffic before it reaches PHP, which may parse some request types first.

    Client identity still uses REMOTE_ADDR, never arbitrary forwarded headers. Configure Apache mod_remoteip or Nginx real_ip using only your trusted proxy CIDRs, and block direct traffic bypassing the proxy. Otherwise clients behind that proxy share application rate limits. TLS termination also needs SESSION_SECURE_COOKIE=true and HTTPS redirection/HSTS at the edge.
